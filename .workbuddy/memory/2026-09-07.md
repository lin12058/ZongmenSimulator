## 接手状态
前一Session已重写 mapgen.js / renderer.js / main.js 为「我的世界式」无限流式区块（六边形区块、地块直径16px、渐入丝滑加载），但存在黑楔形空洞。

## 根因与修复（均已验证）
1. **区块楔形黑洞**：四候选最近中心归属本身正确（全局最近、无重叠），但胞腔在斜向延伸至 14 格，而 `buildChunk` 只扫描 `CHUNK_R+0.5=10.5` 格 → 13~14 格处的楔形地带无人认领。修复：`CHUNK_SCAN=15`（node 脚本验证胞腔最大半径=14，平均每区块 441 格）。
2. **dpr 坐标系错位（最隐蔽）**：GL 渲染以设备像素为 uRes，main.js 相机/视野边界/流式需求集全按 CSS 像素 → dpr=1.5 时 GL 实际渲染世界范围比加载范围大一圈，外环永远黑（只有右上角明显，因左边有预载环遮掩）。修复：renderer 增加 `this.dpr`，hex/post 两 pass 的 uRes 一律传 `fboW/dpr`（NDC 与分辨率无关，FBO 仍设备分辨率高清渲染），同时顺带修正了 overlay 标注与 GL 地图的 dpr 缩放错位。
3. **流式需求集**：旧「4角各自3x3邻域」在低缩放漏屏幕中部区块。改为：视野四角色坐标包围盒 + 外扩 `CHUNK_SCAN+CHUNK_S`（胞腔半径+预载一圈）→ 区块索引范围覆盖式枚举；队列积压>6 时每帧构建 2 个。
4. **小地图**：点击换算错误（误用 backing 尺寸 432 且 y 也误用 132）→ 修正为 132×88 基准 × SCALE 6；刷新节流 `(dirty && >0.4s) || >1.5s`，避免区块生成期间逐帧 1.2 万格采样卡顿。
5. **内容**：灵脉海拔阈值 0.76→0.72（初始视野灵脉 0→3）；道路 z≥0.8、灵脉 z≥0.7 才绘制（远景无意义且避免 A* 批量首算卡帧）。

## 道路 A* 帧内卡顿修复（二轮）
- 根因确认：roadsNear 中 astar 失败不缓存（临海聚落每帧重跑全图探索）+ 首算发生在 drawOverlay 绘制帧；次要：三大缓存满 15 万条整体 clear() 造成周期性重算尖峰、虚线描边开销随 zoom² 增长。
- 修复（mapgen.js + main.js）：①roadFail Set 失败缓存（判定一次终身跳过，init 时清空）；②roadsNear(i,j,maxNew) 预算制，绘制帧传 0 纯读缓存；③新增 warmRoadsStep(camQ,camR) 主循环渐进预热，每帧至多 1 条 A*（z≥0.8 才跑，5×5 区域格旋转扫描）；④elev/field/veinNear 满额改 evictHalf 淘汰旧一半；⑤z>2.4 道路虚线改实线；⑥信息面板点击 roadsNear 预算 1。
- Node 实测：4 遍收敛，收敛后绘制帧调用 1000 次=0ms；warmRoadsStep 11 帧补齐。残留：单条病态失败 A*（海岛聚落 60000 节点 guard 跑满）单次仍可达 ~550ms，因 roadFail 终身只发生一次。
