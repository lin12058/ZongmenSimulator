## 预览页修复：file:// 拦截 + 六边形几何（关键教训）
- **file:// 下 `<script src>` 跨目录加载被 Chrome 拦截**是"页面空白 / MapGen is not defined"的根因；相对路径/绝对 file:// 路径都不稳。
  → 最终解法：**把 noise.js + mapgen.js 源码整体内联进 HTML**（完全自包含，双击即用，不开 HTTP 服务）。
  内联用 Python 脚本正则替换两个 `<script src>` 块完成；文件约 52KB，含 3 个脚本块（noise / mapgen / 渲染）。
- **六边形几何铁律**：晶格节点 (i,j) 的地块坐标为 `(i*CL, j*CL)`，经 tileToWorld 后**天然构成尖顶六边形网格**：
  六边形世界半径 = `HEX_R*CL`，横向邻距 = `√3*HEX_R*CL`，纵向邻距 = `1.5*HEX_R*CL`（已实测与理论值精确吻合）。
  → 直接以 tileToWorld 定位即可严格平铺；**不要再自造"错行砖块"布局**（用 cm.q/CL 贴均匀网格会错位，是上一版"晶格有问题"的原因）。
- 上一版两个 bug 教训：①改布局时绕过了 camX/camY → 拖拽失效（凡绘制坐标必须统一过 `ws()` 相机换算）；
  ②用 jittered 真实坐标 `cm.q/CL` 去贴规则网格 → 错位/重叠。
- 现版本：视口四角反解出晶格索引范围（`screenToLattice`）遍历；群落六边形画在晶格节点，灵脉按真实坐标画在格内；
  名字旁显示 `MapGen.hexDist(v.q,v.r,0,0)` 距中枢格数；`fitScale()` 初始适配约 4 个群落格；MIN/MAX_SCALE=0.02/8。
- 验证手段：Node 里 `eval(内联引擎块)` 后直接算 tileToWorld 邻距 + 统计 communityOf 命中，可在无浏览器下校验几何（9×9 晶格含 43 个群落）。

## 预览页渲染层整体重写（打补丁越改越乱后的终结方案）
- 用户连续反馈：「不能拖动/晶格有问题」→「晶格写反了，越小反而越大」→「越改越奇怪，整体重写」。教训：**几何布局反复打补丁会互相污染，应一次性重写渲染层**。
- **重写手法**（可复用）：用 Python 按锚点 `<script>\n(function(){\n'use strict';` 截出「HTML+CSS+内联引擎」头部，
  新渲染脚本单独写成文件，再 `head + '<script>' + body + '</script></body></html>'` 拼回 —— 只换渲染层，不touch引擎与页面结构。
- **最终几何模型（已是定案，别再改布局）**：
  - 全代码唯一换算入口：`toScreen(wx,wy)` = `wrap尺寸/2 + world*scale + cam`；反向 `toWorld` 用于视口反解。
  - 晶格节点 (i,j) → 地块 (i*CL, j*CL) → tileToWorld → toScreen。天然尖顶六边形平铺（横距 √3·HEX_R·CL，纵距 1.5·HEX_R·CL）。
  - 六边形顶点角 `60k-90`（尖顶）；一个格子的屏幕半径 = `HEX_R*CL*scale`。
  - 视口四角 toWorld → 反解 i/j 范围 → 只画可见格；MAXSPAN=160 防 scale 过小时枚举爆炸；格子半径 <3px 不画网格线/灵脉。
- **缩放铁律（本次核心 bug）**：`scale` 只由滚轮控制，且以指针为锚点。**初始 scale 用固定基准 `BASE_TARGET_COMM_CL=150` 算一次，绝不随 COMM_CL 变**
  ——之前 `fitScale(CL)` 会反向补偿（CL 调小→scale 拉大→格子看着更大），这就是"写反了"的根因。
  正确行为：拖 COMM_CL → 格子屏幕尺寸单调变化（实测 80/150/320 → 43/81/172 px）。
- 名字标注：大灵脉（cellPx>16 时）显示 `名称 ·N格`（hexDist 到中枢）；中灵脉在 cellPx>34 时也标。
- 提示条实时显示缩放百分比；统计面板显示 视野半径/晶格间距/六边形屏幕半径/含脉群落/大中小灵脉计数。
- 内联引擎时注意：**渲染脚本必须在噪声/地图引擎两个 script 块之后**（同页面共享 window），file:// 双击即可用，无需 HTTP 服务。

## 预览页两个新 bug（拖动残影 / 调参数不重建）
- **拖动残影**根因：`draw()` 开头 `ctx.setTransform(1,0,0,1,0,0)` 把 `resize()` 设的 DPR 变换**重置**了，
  于是 `clearRect(0,0,W,H)` 只清了逻辑像素（画布实际是 W*dpr）→ 右下残影 + 后续绘制全部丢失 DPR 缩放。
  修法：清屏用 `save()→setTransform(1..0)→clearRect(0,0,cv.width,cv.height)→restore()`（用**物理像素**全尺寸），
  **不要**让 draw 永久重置变换，DPR 变换由 resize 统一设置并保持。
- **调 COMM_CL 其他内容不跟着变**根因：滑块只改了 cellPx 底网尺寸 + 重画，**从未调用 `MapGen.configure({COMM_CL})`**，
  所以群落/灵脉仍按旧参数（尤其 commCache 里全是旧值）。这不是"图片位置"问题而是**没重新生成世界**。
  修法：`commClEl.onchange` 里 `MapGen.configure({COMM_CL:CL})`（该函数会清 comm/elev/vein/region/settle/road 全部缓存）
  → 重置相机与 scale → draw，`communityOf` 即按新间距重新播种。
  实测 COMM_CL 150→90 群落分布确实改变（43→51 个），证明重建生效。
  用 `onchange` 而非 `oninput`：拖动过程中不重算（几千个群落会卡）。
- **通用教训**：预览类调试页「调参」必须落到真正的生成函数（configure/init）并清缓存，
  否则只改了渲染层的视觉参数，看起来"动了但内容没变"。

## 预览页：重新生成 = 换随机种子
- 「重新生成」按钮原来只用当前种子原样重跑（看起来"什么都没改"）→ 改为每次点击 `randomSeed()` 生成新种子（`'seed-' + (random*0xffffffff).toString(36)`）写入种子框再 `MapGen.init(新种子)`。
- **其他 CFG 参数保持不变**（`applyAllCfg()` 照旧应用面板当前值）→ 只换世界布局，不换规则。
- 种子框支持手动输入 + 回车（`keydown` Enter）用该种子重新生成；HTML 种子框去掉 `value="demo1"`、加 placeholder，启动时也自动给一个随机种子。
- 实测：200 次生成 200 个不同种子；不同种子 (0,0) 群落位置不同（-28 vs 23），世界确实随种子变化。
