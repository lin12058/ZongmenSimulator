## 脚本化城市迭代 —— 资料调研（只调研，未定案）

用户要求：出一份方案，用一段 JS 脚本放进 V8 引擎迭代，**模拟玩家的城市迭代**；本轮**先只整理网上资料成文档**，之后再讨论。

产出：`待办事项/脚本化城市迭代-资料调研.md`（v1）。

### 本轮读代码得到的关键事实（对本项目后续有用）

- **城市内部演化能力为零**：`growTownFootprint(id,type,q,r)` 是**纯函数 + 按 id 缓存**（`townCache`, `mapgen.js:180`），签名里**没有时间维度** ⇒ 同一座城永远长同一个样。要做迭代只有两条路：(a) 纯函数加 tier/时间 维度；(b) 加"演化覆盖层"（照抄 ext 层的零拷贝思路）。
- **实体骨架字段已就位**：`tier / state(0活跃1被毁2刷新中3事件态) / owner / expireTs / pop` 已落地（`mapgen.js:1207-1218`），服务端恒 `state=0/owner=''/expireTs=0`，注释写明"字段先落地供事件系统接入"。
- **足迹包已独立落库**：`settleJson`（`mapgen-server.js:123-145`），注释原文"建筑足迹『后续会演化, 必须持久化』"。
- **一号约束 = `commitPlace` 405~443ms 同步门闩占用**（`mapgen-server.js:429-479` 七步）。单次放 1 座可接受；脚本一轮建 10 座 = 4 秒级阻塞 ⇒ 决定了整个架构必须是**分批/异步执行**。
- 现成 tick 挂载点：`MaintenanceLoopAsync`（`MapWorldService.cs:131/1338`）。
- 已有的 P2 预留设计：方案 §5.1（服务端 tick + 客户端拉帧 7）、§5.2（资源→人口→升阶；**建筑追加必须用 `(EntId,Tier)` 纯函数 hash，禁随机数**）。§七 与 §10.4 明确写了「✗ NPC 城市迭代」未做。

### 调研结论（写进文档，供讨论）

- 三条候选路线：**A 意图-执行分离（Screeps 式）/ B 演化规则内联（CA 式）/ C 混合分层**；倾向 **C**（决策在脚本、校验在引擎、执行在 `commitPlace`；脚本只提意图不写世界）。
- 最值得照搬：**Screeps 的 runner/processor 分离 + CPU limit/bucket**；**OpenRA/Klotho/TickForge 的确定性纪律**（我们已用 `hash01` 纯函数哈希，天然满足，只需禁止新增 `Math.random()/Date.now()`）。
- 离线推进两条工业实现（闭式 delta-time / 分批补跑），以及"tick 拉长会让每-tick 触发器失真"的坑。
- 城市形态指标（扩展强度 R / 紧凑度 C=2√(πA)/P / 分形维数 D=2ln(P/4)/ln(A)）**只作跨轮趋势与 A/B 归因判据，绝不作绝对值阈值**（遵守既有"判据三防"）。
- 待用户拍板 8 条（脚本扮演谁 / 迭代指哪一层 / 推进模型 / 权限边界 / 预算模型 / 是否要求 replay parity / 交付形态 / 是否推翻"不做清单"）。

## 游戏时钟与 Tick 演化框架 —— 设计稿（只设计，未开工）

用户要求：C# 侧 GameTick 框架，**1 秒 1 tick = 游戏 1 日**，360 日/年、30 日/月、四
季；`nextTick` lazy（避免每 tick 都算）；两步走（先**解耦**算清哪些能分开 → 再进 V8 执行）；
按区块分区、完全独立的直接算；用**消费队列**。产出：`docs/游戏时钟与Tick演化框架方案.md`（v1）。

### 本轮定案 / 发现的硬约束（后续实施必看）

- ⚠ **「进 V8 并行」必须澄清**：`JsWorldVm.Call` 全程持 `SemaphoreSlim _gate`、`V8ScriptEngine`
  单线程 ⇒ **单世界内不可能真并行**；给同世界配 N 个 worker = 全堵门闩（虚假并行）。
  合法兑现只有三条：① **批量化**（N job → 1 次 `tickBatch` 调用，消 N-1 次跨界+JSON 编解码，
  ★MVP 主手段）② **跨世界多 VM**（随 `MaxSeeds` 免费）③ 单世界分片（不可行：引擎缓存全全局）。
- **出口加在 `mapgen-server.js`（服务端适配层），不新建 js 文件** ⇒ 一次避开四个挂载点：
  bundle 数组 / `JsEngineHost.Call` switch / **`MapWsHandler.EngineScriptOrder`（不该加）** /
  **`ComputeEngineHash`（不该加，加了会让前端误判引擎升级）** / `sync_preview_inline.mjs`。
- **队列按「资源」划不按业务划**：`v8Queue`(并发 1) + `cpuQueue`(并发 核数-1)，两条 Channel
  `FullMode=Wait` 做背压。合成一条 = 虚假并行 + 饿死人类请求。
- **双缓冲快照 + 定序合并**是把并行正确性「降级」的关键：job 只读快照、只写私有 Patch，
  单线程合流器按 `(Layer, SortKey, Id)` 全序 apply。快照粒度用 COW，不深拷贝全图。
- **三层频率把全局耦合赶去低频**：L0 局部 1 日 / L1 邻域 1 月季 / L2 全局 1 年。
  ⚠ L2 必须串行：`mapgen-config.js` 已写明「路径形状取决于**建路顺序**」（A\* 主动并线
  `ROAD_W_ROAD=2`）⇒ 并行重算道路 = 不确定的世界。
- 解耦必须看 `EngineCaches`（roadCache/settleCache/townCache/siteScoreCache），**只看 Writes
  会误判**「不同区块的城镇生长互不相干」（其实同写 `townCache` 不同 key）。⚠ 引擎内 RNG 若按
  调用顺序取值 ⇒ 并行必变序列 ⇒ 破坏确定性（须改成 `seed+jobId` 派生独立流）。
- ⚠ **红线：tick 只许改实体层（settle/poi/comm/region），绝不许改 `chunk` 地形** —— 否则
  「前端按 seed 自算地形 + WS `mask` 去 CHUNK 位(=30)」的前提当场崩塌。判据
  `check_tick_chunk_immutable.mjs`（跑 1000 tick 后 chunk 逐字节不变）。
- 时钟存**独立表 `WorldClock`**（⚠ 不能塞 `Data`，`PruneExcept` 静默删）；`expireTs` 语义应
  改为** tick 号**（devdoc §二 明确留了这个钩子，本框架就是来还债的）。
- **`BumpBlockRev` 的 C5 契约原文写着「接入事件/演化系统时，这是第一处必须挂上的钩子」**
  ⇒ 合流器就是那个调用者：每个影响可变图层的 Patch 必须 Bump，否则前端带旧 rev 重拉被判
  「未变化」= 改了没反应且不报错。
- **tick 与人类请求抢 `_gate`**：V8 阶段用 `Wait(TickGateWaitMs)` 让位（拿不到就跳过本 tick 的
  V8 部分），并对齐既有 `PlaceCommitMinGapMs=700` 的思路。L2 道路重算 405~443ms ⇒ 必须低频+分帧。
- `WsFrame` **7 号已被 P2「城市迭代」预留**（`MapMessages.cs:220` 注释），时钟/城市查询正好用它。
- 分期：P1 时钟+小顶堆调度+L0 批量 → P2 L1+双缓冲+`BumpBlockRev` 接线 → P3 L2 全局+跨世界并行。
- 待拍板 6 条：离线是否追补（默认冻结）/ 在线状态是否影响时钟（建议否）/ L0 周期粒度 /
  `TimedEvent` 是否本轮做 / 前端每秒一帧 vs 本地插值 / `expireTs` 沿用 int64 还是新增 `expireTick`。

> 注：本轮与上文「脚本化城市迭代 资料调研」同属 P2 链路 —— 那份是「演化**内容**怎么定义」，
> 本篇是「演化**何时跑、怎么调度**」，实施时两份要合读。

### 本轮核实到的**硬事实**（实施必看）

- **ClearScript 是 7.4.5**（`Zongmen.csproj`）⇒ `IArrayBuffer` 只有 `byte[]` 重载；**`ReadBytes/WriteBytes(Span<>)` 与 `InvokeWithDirectAccess` 是 7.5.1+**；`SharedArrayBuffer` 跨 runtime 共享 7.2+ 有。⇒ 「零拷贝」要升级（换原生 dll，须全量回归）。⚠ **宿主如何拿到 `IArrayBuffer` 句柄必须 spike 验证，不假设 API 名**。
- **引擎里没有 pb 写入口**：`web/js/pb.js` 头注释写着「**仅解码(前端只读不写)**」⇒ 边界换 protobuf 的硬前置是**新增 `pben.js`**，且其挂载点与业务出口不同：✅ bundle 数组、❌ `EngineScriptOrder`、❌ `ComputeEngineHash`（注释原文：指纹只算下发前端的三件套，**不含 `mapgen-server.js`**）。
- **`JsEngineHost` 的 17 个出口全是 `(string)_svc.xxxJson(...)`** ⇒ 新增 `CallBytes` 必须**与 `Call` 并列**，不能改签名。
- **`GZipCodec`（`Protocol/Codecs.cs`）+ `GzUnwrap`（`MapWorldService:662`）** 已就位 ⇒ 「V8 前解压、V8 后压缩」可直接复用，不必新写。
- **`BlockRevs`**：`Chunk/Region/Settle/Poi/Comm` + `Interlocked.Increment`（C5 已做原子化）；`TileMask` 位驱动 Bump。
- ⚠ **`growTownFootprint(id,type,q,r)` 不读 pop/tier** ⇒ 「足迹生长」在当前引擎里**根本不受演化参数影响**。要生长必须加维度；最优雅解法 = **`$base + evoIn` 扩展层**（照抄 `settlementsFor = $base + extIn` 零拷贝思路），从而避开改 `mapgen.js` ⇒ 不改 `ComputeEngineHash` ⇒ 前端不会误判引擎升级。

### v2 新增方案要点

- **`TickVmPool`（无状态执行器池）**：预热 S = `ProcessorCount-1` 个 VM，输入「快照 proto + job 批」、输出「patch proto」，权威态在 C#/SQLite。⇒ ① 真并行；② **与读路径 VM 两套 ⇒ 人类请求门闩零争用**（v1 的 `TryWait` 让位逻辑**不再需要**）；③ **可随时 Drop 重建**（无状态 ⇒ 丢弃零损失，泄漏/漂移/异常直接扔）。
- ⚠ **冷启账**：`new V8ScriptEngine + Evaluate(bundle) + init(seed)` 数百 ms（`JsWorldVm` 注释原文）⇒ **「用完即丢」在 1Hz tick 上不可行**，必须池化 + 复用。
- **实体级聚合 job**（`TownEvolve` 合并生长+升降级）：一次快照、一次跨界、产出两个 patch ⇒ 顺带消掉「同 `stId` 不可并行」的限制。
- **gzip 唯一规则**：压缩属「存储/传输」层，**V8 边界恒为未压缩裸 proto**。链路 = DB(gzip) → 解压 → proto → V8 → proto → 再 gzip → 落库/下发。
- **分段计时**（`t_gz_unwrap/t_pb_ser/t_xfer_in/t_js/t_xfer_out/t_apply`）⇒ 否则「优化」是猜的（`t_total` 变大可能是快照膨胀而不是 JS 算得多）。`TickPerf` 独立表 + `/stats` 用 **P50/P95 不用均值**。
- 判据新增 8 条，其中 `spike_v8_abuffer` 是 **P0 前置**（失败则降级 7.5+ 或 base64+proto）；`check_tick_dt`（「1×dt30」≡「30×dt1」）、`check_tick_phase`（相位不改周期 + 分桶均匀性）、`check_tick_no_pollute`（`$base` 零污染）、`check_tick_pb_roundtrip`（三处实现字段号对齐）。
- 待拍板 10 条（增：ClearScript 是否升 7.5 / `TickVmPool` 的 S / L0 摊批的 M / 帧 7 是否明文 / `pben.js` 独立文件 vs 内联）。
