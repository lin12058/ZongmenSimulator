## 小队面板第八轮（00:10 起）· 跨队拖动 / 空队接人 / 移空合并

用户原话：「现在只有两个小队在一起的适合才能互相移动！你看一下这个数据有没有标记的，数据接口有没有位置和小队的？创建小队的时候小队为空的时候可以移动，如果移动的没人时候背包会自动合并这个要记清楚」。

### 查清的事实（先答问题再动手）
- **前端数据没有 squadId/pos 字段**：归属与站位唯一真源 = `squads[i].members` 的数组顺序。
- **接口也没有**：`crew-bridge.js` 仍是单个 `squad{members[]}`，没有 `squads[]`、没有 position 字段。
- 原来的拖动是「每队一个独立 host」，所以弟子**拖不出本队** —— 这才是"只有两个小队在一起才能互相移动"的观感来源（真正能换队的只有行尾「移」菜单）。

### 改了什么
- `crew-model.js`：新增 `locatePawn(state,id)→{squad,name,pos,size}`、`movePawn(state,id,toSq,toPos)`（返回 `fromEmpty/toWasEmpty`，空队可收人）；`probe()` 增加 `assign:[{id,squad,pos}]` 全员标记。
- `crew-panel.js`：
  - 拖动从「每队各自 bindSort」改为 `bindPawnDrags(#sqSecs)`：按指针 y 判目标段，**拖到别队就换队**，位置按行中线插；空队也接得住。
  - 空队不再省略 `.rp-list`（改渲染 `.rp-list.empty` + 提示块），否则新建空队接不住人。
  - 松手 `applyPawnDrop` 按各段 DOM 行序写回 `members`；兜底：没落进任何段的人回第一队。
  - `movePawnTo` 统一走 `M.movePawn`；`fromEmpty` ⇒ toast「『X』已空 · 负重 0（物品都在宗门背包，不会丢）」。
  - `probe()` 增加 `assign` 与 `emptyLists`。
- `crew-panel.css`：`.rp-list.empty`（min-height 46px + 内描边）／`.sq-sec.drop` 高亮／`.rp-row.dragging` z-index。
- `docs/小队背包数据接口.md` 新增 §13（标记口径 / 接口缺什么 / 空队与背包合并规则）。
- `verify/_crew_harness.html` 新增 J 段 21 条 ⇒ **148 PASS / 0 FAIL**。

### 两个真教训
1. **bash heredoc `>>` 在这台机器上会写到文件开头并覆盖原字节**（不是追加）。本轮把 `docs/小队背包数据接口.md` 开头 34 行写坏了，最后从会话记录里翻出当初 `Write` 的快照（`0e2d23d1…jsonl`）才复原。以后中文 md 一律用 Write/Edit 工具。
2. **验收台默认只有 1 支小队**（`demoSquad(6)` 默认 teams=1）：J 段直接取 `getSquads()[1].id` 会 undefined 崩掉。断言里要先 `addSquad()` 并把人调过去，再测跨队。

判据：`_crew_harness.html?test=1` **148 PASS / 0 FAIL**；真机 `verify/_c17_cross.png`（两段纵向、行尾「移」）。

## 第九轮（00:35）· 定事件流：只发事件，不发整份契约

用户原话：「现在把这个前端面板的操作整合到 小队背包数据接口.md 里面 每个事件单独的事件，只发送事件，而不是直接把改完的数据发到后端；现在先整理一下接口我来确定哪些要还是不要」→ 确认后「OK写入接口中，注意我们是 protobuffer 但是事件可以用json来传，因为数据量不大」。

### 落盘
`docs/小队背包数据接口.md` 新增 **§十四 事件流（Event-only）**，14.0~14.10 十小节；同时把 §七 step 3 的 `onChange + ev.contract + PUT` 示例改成 `onEvent + POST /api/crew/events`（旧写法标作废），§九 已知边界加一行「事件流未实现」。

### 定下来的口径（写死在文档里）
- **9 条事件**：`squad.create/rename/disband/move` + `member.move` + `item.equip/unequip/use` + `job.priority`。
- **砍掉** `member.reorder` / `squad.reorder` —— 一次拖动只挪**一个人/一支队**，`move` 已覆盖，不发整序数组。
- **不发事件**：`curSquad` / `selId` / `tab` / `filter` / `stashSel` / `secOpen` / 拖动态 —— 纯本地偏好。
- **暂不定义**：`item.move` / `item.drop` / `job.assign` / `member.recruit` / `queue.reorder` / `squad.capacity`（无 UI，别接一半）。
- **编码**：事件 JSON（单条 150~400B、低频、要能读日志），protobuf 只留地图 WS；不为事件加 `.proto`。
- **信封**：`v / id(幂等键) / seq / base(乐观 rev) / at(仅审计) / type / data(只放 id + 目标值)`。
- **冲突**：本地先改 → 300ms 合并窗口 → `base != rev` 返回 `conflict + resync + 整份 state` → 前端整份重装。
- **唯一非乐观**：`squad.create`（等往返拿真 `squadId`，避免临时 id 映射）。
- **服务端**：`CrewEvent(Id,At)` 独立表做 5 分钟去重（⚠ 塞 `Data` 会被 `PruneExcept` 清）；`Crew` 加 `Rev INT`。
- **一次手势 = 1 条**：拖动过程零事件；`×` 第一次点击 0 条；`job.priority` 发**目标值**不发"下一档"。
