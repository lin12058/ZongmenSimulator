## ★ push 失败的两种病因（2026-09-10 补正，此前判断过于绝对）
1. **凭据弹窗没人点 → 挂起、无任何输出**：本机 push 会弹 GitHub 凭据授权窗口，未点时 `git push` **不报错也不返回**（实测 `timeout 300` 静默超时、exit=124）。**处理：让用户点一下弹窗，一次即过**（实测重试 6 次全败 → 用户点弹窗后 1 次成功）。此时**不要**加 `GIT_TERMINAL_PROMPT=0`（它会让凭据弹窗直接失败而非弹出），也不要盲目重试。
2. **schannel 握手失败 → 快速显式报错**：`fatal: unable to access '…': schannel: failed to receive handshake, SSL/TLS connection failed`，exit=128，几秒内返回。**这是真·网络/TLS 层问题，不是弹窗**。处理：换策略重试 —— `-c http.version=HTTP/1.1` / `-c http.sslBackend=openssl` / 稍后再试。本次 3 个只读 `ls-remote` 也全被它挡住，说明是**本机到 github 的 TLS 通道间歇性不可用**（与当天 `.git` 被删、chrome 被 SIGTERM 同属「本机安全/管控代理干扰」现象群）。
- **判别口诀**：**挂起无输出 = 看弹窗；快速报 schannel = 换策略重试/稍后再试**。
