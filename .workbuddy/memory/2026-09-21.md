# 2026-09-21 工作日志

## ⚠ v2 修订（用户否决 v1 方向后）

用户原话补全三条需求：**「玩家可以随便放 / 城市之间不能太接近，根据需要根据城镇的规模来设置
属于的领地，如果玩家 8 格附近的有城市的中心就不允许建造 / 地图上面的路径会重新算」**。

**v1 的方向判定错误**：v1 主张「服务端出候选位、玩家只挑一个」→ 被否决。
v2 改为**自由落点 + 领地间距约束**。教训：**用户说「怎么放置」时不要自作主张加"择优"限制** ——
「随便放」是体验诉求，约束应该做在**空间关系**上（领地/间距），不是做在**候选生成**上。

### v2 的核心决策

1. **自由落点**：除「领地/间距」这一条几何规则外，不做任何地形择优。
   ⇒ 明确放弃「玩家也只能落在 `siteScore` 高的地方」（`siteScore` 只服务自动生成）。
2. **规模 → 领地半径 `DOMAIN_R`**（真源 `mapgen-config.js`，C# 镜像）：
   `{ city:8, town:6, sect3:8, sect2:7, sect1:6, village:4, fishing:4, poi:0 }`。
   用 **`tier`** 做映射（不用 `pop` —— pop 连续且 `inVeinDomain` 时 ×1.3，不可预期）。
   `city=8` 就是用户说的「8 格」。`poi` 不设领地。
3. **判定口径 = 单向（甲解）**：`hexDist(落点, 既有聚落中心) ≥ 该聚落的 DOMAIN_R`，
   只看既有聚落的领地，与玩家自己规模无关。拿新落点量别人，而不是量半径之和。
4. **道路只需增量重算**（关键结论）：既有道路是**纯地形 A*（恒不传 `roadTiles`）+ 顺序无关**，
   ⇒ 「新增一个聚落」只产生「含该聚落端点的**新边**」，**旧边一条都不用重算**。
   玩家边走**独立双通道**（`playerEdgesFor`），**不进 `demandCache`** ⇒
   `demandCache`/`skeletonCache` 对自动生成部分完全不失效。
5. **两套"新鲜度"系统必须都通知**（最隐蔽的坑）：
   ① `rev`（`BumpBlockRev` ⇒ 客户端缓存有效性）② `roadVer`（⇒ tile 的 `onRoad` 是否正确）。
   **互不相通**。`mapgen-server.js:101` 注释原文预警：「BlockRevs.Region 只在显式 BumpBlockRev
   时变化, 不随 roadVer 前进, 客户端不会自动重拉。」⇒ 放置必须**显式 Bump Region 位** +
   **主动 `ObserveRoadVer`**，否则症状是「改了没反应」（无异常无日志）。
6. **区域包重算是性能大头**：`REGION_ROAD_BUDGET=9999` 注释实测「首请求 ~195.8ms」且**在 V8
   门闩内同步跑** ⇒ 重算 9 个区域包 ≈ 1.8s 门闩占用。建议**异步 + 二次 Bump**
   （宗门立刻可见，路稍后接上，响应带 `RoadsReady=false`）。

### ⚠⚠ 本轮算出的最重要结论：校验必须扫 **2 环邻域（25 个区域格）**，1 环不够

**推导**（全部真源值已核实）：
- 区域格间距 `REGION_M = 18`（`mapgen.js:45`）
- 聚落锚点抖动 = `0.35 × 18 = 6.3` 格（`mapgen.js:1166~1167`）
- 锚点后 `pickSettlementCenter` 再选半径 `PROSPECT_R = 4` 格
- ⇒ **单侧最大偏移 = 10.3 格**
- ⇒ 第 1 环聚落最近可能距我 `18 − 10.3 = ` **7.7 格**（**< 8！在禁区内却查不到**）
- ⇒ 第 2 环 `36 − 10.3 = 25.7` 格（安全）
- ⇒ **所需环数 = `ceil((8 + 10.3) / 18) = 2`，共 25 个区域格**

**为什么危险**：按直觉写 1 环（9 格）不会报错、不会抛异常，只是**偶尔**放行
（只在两格中心错位到 7.7~8 格时发生，实测 296 个聚落里有 **20 对**落在这个带，≈7%）。
这种「偶发、无日志、部分场景才错」的 bug 极难定位。

**已钉成判据**：`verify/check_place_neighborhood.mjs`（新增，已注册进 `run_regression.mjs`
的离线组，7 PASS / 1.2s）。

### 判据写作教训（本轮踩到并修好）

**空真（vacuous truth）**：第一版 `check_place_neighborhood.mjs` 的 D 段只在 `< 8` 格里找样本，
而 `SETTLE_MIN_DIST=7` 已把自动聚落推开 ⇒ `hitsInDomain` 恒为 0 ⇒ 断言**空真、无鉴别力**。
改法：探针半径取 `SETTLE_MIN_DIST + 1 = 8`（恰好跨过抑制阈值那一带），拿到 **20 对**真实样本；
并加一条显式断言「`hitsInDomain > 0`，否则 FAIL」。
⇒ 对应工程纪律「参照系不能自证 / 空真不可接受」（skill §32），**以后写抽样判据都要加这条**。

## 玩家放置宗门 + 城市迭代 —— 方案文档 v1（已被 v2 取代，保留以备查）

产出 `docs/玩家宗门放置与城市迭代方案.md`。用户要求「先思考方案，形成文档md」。

### v1 的方案核心决策（方向被用户否决，见上方 v2 修订）

1. ~~**只能落在服务端算出的候选位上（3~5 个），不做任意格自由放**~~ ← **已被否决**
   理由：自由落点要把 `siteScore`/`landuseOf`/`SETTLE_MIN_DIST`/灵脉缓冲整套判据重写到客户端做预览，
   必然两份实现漂移。选「服务端出候选」⇒ 判据只有一份，玩家仍有选择权。
   ✅ 已核实 `mapgen.js` 1855~ 导出清单里 `rawSettlementsFor`/`pickSettlementCenter`/`siteScore`/
   `landuseOf`/`coastalAt`/`spiritAt`/`prospectArea` **全部已导出** ⇒ 候选枚举只需一个薄封装，
   **不需要新引擎算法**。

2. **接口走 WS 新帧类型 5/6/7，不走 HTTP**。
   依据 `MapEndpoints.cs` 头注释「HTTP 不再保留任何拉图接口」；HTTP 那条道在本工程被划给
   「不拉图的小 JSON」（`/api/world/*` 是唯一先例）。帧号沿用既有 **双向共用** 风格（Ping=3/Pong=3 同号）。

3. **数据落新独立表 `PlayerPlace`（同库不同表），绝不写 `Data(Key,Value)`**。
   依据 `PruneExcept` 的 `DELETE FROM Data WHERE NOT (Key LIKE 'w:%')` —— 非 `w:` 前缀的行每 2 分钟被
   **静默删除**。`WorldLedger` 已为此单开表，玩家资产同理。这是**数据丢失级**的坑。

4. **叠加层（overlay）设计：自动生成产物 + 玩家实体 = 最终视图，绝不回写引擎缓存**。
   三条铁律：① 不调 `MG.addSettlement()` 之类往引擎塞东西 ② 玩家实体不参与自动生成的概率/选址
   ③ `siteScore` 只在候选生成时读。代价 = 可能与 NPC 聚落视觉上「挤」（刚好 7 格），刻意接受。
   红利 = `_mem`/`_rawCache`/`_settlePackCache`（对自动产物）**无需失效**，只有 `_settlePackCache`
   在放置路径要显式 Remove。

5. **城市迭代 = 服务端 tick 推进 + 客户端拉取**，保持 `MapWsHandler` 「服务器不主动推送」不变。
   不选客户端驱动（同一世界在不同机器上进度不同 ⇒ 世界不权威）；不做服务端推送（要一整套订阅/背压/
   断线重放基建，收益为零）。建筑追加的确定性来源必须是 **`(EntId, Tier)` 纯函数 hash** 而非随机数
   （tick 可能重启重跑同一拍，随机数会让建筑「跳变」）。

6. **复用不新增**：`SettlementDto`/`PlaceEntity` 的 `Owner/Tier/State/ExpireTs` **字段号一个不改**；
   不新增图层位（玩家宗门复用 `TileMask.Settle`）；帧 5/6/7 复用既有 `WsSession.Authed`。
   玩家实体 id 前缀 `p_`（自动是 `i_j_k`/`i_j_p`）⇒ 天然不撞 id。

### 本轮核实的关键常量（`mapgen-config.js` 原文）

- `TOWN_R = 3` ⇒ 足迹盘 37 格 ⇒ **足迹跨块是必然而非偶然**（`DirtyBlocks` 必须服务端按包围盒算）。
- `SETTLE_MIN_DIST = 7`，注释原文写明推导：「**下限**：足迹半径 TOWN_R=3 ⇒ 中心距 < 7 时两镇地盘
  **必然重叠**；取 7 恰好」⇒ 判据不是随手取数，是几何必然。
- `TOWN_BUILD_MAX.sect = 16` ⇒ P2 玩家升阶受同量级上限约束。
- `SETTLE_VEIN_FOOT_PAD = 2`、`SEA_SETTLE_MIN_SPIRIT = 0.20`、`SEA_SETTLE_NEAR_LAND = 1`、`PROSPECT_R = 4`。

### 新增的两个「必加不变量」断言（本方案最易被后人破坏处）

1. 放置前后**自动生成的世界逐字节不变**（chunk/region/comm/settle 包 hash 全等）——
   证明叠加层没污染引擎。
2. `Data` 表行数在放置前后不变 —— 证明玩家数据没混进 `Data`。

### 已核实的 `engineHash` 断言（纯新增导出不会误红）

- `verify/check_calc_local.mjs:340` 只校验 engineHash **形态**，不是「等于常量」。
- `verify/frontend_smoke.mjs:585` 只扫接线正则 `noteEngineHash(MC.engineHash())` + `verifyHash(`。
- `verify/check_world_ledger.mjs:143` 只要求 `meta.engineHash` 为真值。
⇒ **没有「指纹恒定」类断言**，纯新增导出安全。

### 已知风险（写进文档 §八）
