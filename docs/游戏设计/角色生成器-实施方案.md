# 角色生成器 · 实施方案（可招募弟子）

> 日期 2026-11-25 ｜ 状态：**生成器已落盘，尚未接入 UI / 服务端**
> 真源代码：`Server/Zongmen/Engine/js/chargen.js`（出口 `window.Chargen`）

---

## 一、这份文档解决什么

开局要在**地图上的聚落**随机招人。需要一个**确定性、可复现、纯函数**的弟子生成器，产出的对象直接能被
`web/js/crew/` 那一套（`CrewBridge.validate/hydrate` → `CrewModel.attrs` → `CrewPanel`）接受。

**不做**的事：不算派生值（气血/攻防/命中都现算）、不落库、不管 UI、不管定价与名额。

### 三个生成器别混

| 名字 | 位置 | 用途 | 口径 |
|---|---|---|---|
| `CrewModel.demoSquad` | `web/js/crew/crew-model.js` | 前端演示数据（6 人 + 48 格背包） | 六道 + 灵根，**境界由天赋推** |
| `CultivatorGen` | `Subsystems/Characters/js/chargen-core.js` | 世界人口（地图热力图 / 名录 NPC） | 数据驱动、正态分布、**另一套字段** |
| **`Chargen`** | `Engine/js/chargen.js` | **玩家可招募弟子** | 本档口径，产 `crew` 契约形状 |

三者互不调用。将来若合并，以 `Chargen` 的字段为准，另两处各写适配层。

## 二、口径来源（设定 + 2026-11-25 定案）

| 来源 | 内容 |
|---|---|
| `docs/游戏设计/角色系统设定表.md` | 弟子 = 灵根 + 天赋 + 特质 + 装备 + 神通 |
| `docs/游戏设计/六道属性体系.md` | 六道是唯一投点处，其余全派生 |
| 用户 2026-11-25 | ① 天赋 **90~180**，不做聚落分级（后期升级加得更多）；⚠ 后改为**平方偏斜**（`90 + 90·rng²`，均值 120），不再均匀，见 §四 ② **只生成凡人（炼气）** ③ 灵根**合计 100**，与觅长生同构；玩家侧**至少一系，最低 20**，系数量按 1/2/3/4/5 = **1%/2.5%/20%/30%/46.5%**（⚠ 追加修正：**初始只有 0/20 两档**，合计退化为 `20×k`、100 仅作纯度分母，见 §三）④ 装备不设品阶门槛，走「灵力驱动」⑤ 神通靠修炼时间，开局没有 ⑥ 特质**只发正面**，负面一律不出（避免玩家嫌弃），并补上「天生魅体」这类异禀 ⑦ 特质必须**把加成量化**、按累计权重抽卡（越强越难出），**不许人均天命** —— 见 §五 |

### 硬约束（生成器必须满足，`selfTest()` 逐条断言）

| 项 | 约束 |
|---|---|
| 灵根 | 五项之和 **恒 = 100**；每项 ∈ {0} ∪ [20,80]；非零项数 = 抽到的 `k` |
| 天赋 | 总量 ∈ [90,180]，六道之和 = 总量，**单道 ≤60**，每道 6 项**单项 ≤60** |
| 特质 | 1~3 条，**全部正面**（`kind` 恒 `pos`），同名/同 `k` 不重复 |
| 装备 | 5 槽类型必须与物品 `kind` 一致；法宝队列 1~4 |
| 神通 | 已学 `slots` = **0**，格数 `cap` = 3 |
| 境界 | 恒为 `炼气期 · 1~3 层` |
| 修为 | `exp > 0` 且 ≤ 炼气段上限（见 §七） |

## 三、灵根

> **2026-11-25 改口径**：初始灵根**只有两档 —— 0（这系不通）或 20（通了）**，不许出现 22/25/28 这类中间值。
> 因此五项**合计不再是 100**，而是 `20 × 系数量`（20/40/60/80/100）。
> "合计 100" 退化成**纯度换算的分母**：纯度 = 本系 / 合计，单系 100%、双系各 50%、三系各 33.3%、四系各 25%、五系各 20%。
> 走高不再靠初始值，而是后续用资源强化（`ROOT_MAIN_WEIGHT` 留着给那时的加点用）。

### 3.1 系数量分布

| k | 概率 | `rng()` 累计阈值 | 合计份数 | 读法 |
|---|---|---|---|---|
| 1 | 1% | `x < 0.010` | 20 | 天灵根（纯度 100%） |
| 2 | 2.5% | `x < 0.035` | 40 | 双灵根（各 50%） |
| 3 | 20% | `x < 0.235` | 60 | 三灵根（各 33.3%） |
| 4 | 30% | `x < 0.535` | 80 | 四灵根（各 25%） |
| 5 | 46.5% | 其余 | 100 | 杂灵根（各 20%） |

### 3.2 分配算法（二值，无余数）

1. 抽 `k` → 从金木水火土里随机挑 `k` 个（**若给了本地灵脉五行，主系优先落该系**，其余随机）。
2. 选中的 `k` 个系各写 **`ROOT_STEP = 20`**，其余写 0。**不切余数**（旧的按权重切 100 已删，`splitWeighted` 一并删除）。
3. `sum = 20k`；`pct[i] = v[i] / sum`（写进 `meta.rootPct`，供 UI 显示纯度）。
4. `main` = 值最大的下标；**五系并列时随机取一个**（不许固定 0，否则所有人的主灵根都像"金"）。

### 3.3 典型结果

| k | `root.v` | 合计 | 纯度 |
|---|---|---|---|
| 1 | 20/0/0/0/0 | 20 | 100% |
| 2 | 20/0/20/0/0 | 40 | 各 50% |
| 3 | 20/20/20/0/0 | 60 | 各 33.3% |
| 4 | 20/20/0/20/20 | 80 | 各 25% |
| 5 | 20×5 | 100 | 各 20% |

> ⚠ **过桥会把合计归一到 100**：`crew-bridge.js:118` 警告、`:274` 按比例缩放（`20/20/20/20 → 25/25/25/25`）。
> 也就是说生成器给的是**份数**，面板里看到的是**纯度百分比**，两者语义等价、不是 bug。
> 若要让面板也显示 0/20，必须改 `crew-model.CFG.ROOT_SUM` 与 `probe` 的合计断言（见 §十四）。

> ⚠ **0 值的语义**：该系永久不通 —— 不能聚这系灵气、不能学这系神通。**"无灵根"（五项全 0）在玩家侧不存在**；
> 若以后要出「无灵根凡人杂役 / 敌修」，必须另加标记，否则 `CrewBridge` 的 `sum≤0 → [20,20,20,20,20]` 兜底会把它们变成五灵根。

## 四、天赋

- 总量 **平方偏斜**，不是均匀：

```js
total = round(90 + 90 * Math.pow(rng(), CFG.TALENT_SKEW))   // SKEW 默认 2
```

  均匀（SKEW=1）会让 150+ 占到 1/3，招募池里一水"两道 60 满"的苗子，稀有度倒挂。

| SKEW | 均值 | ≥150 占比 | ≥165 占比 | 读感 |
|---|---|---|---|---|
| 1（旧，均匀） | 135 | 33% | 17.9% | 满街天才 |
| **2（现行）** | **120** | **18%** | **9.2%** | 大多数是 90~120 的普通苗子 |
| 3 | 112.5 | 12.6% | 2.6% | 更苦，招人全靠熬 |

实测 30000 人（SKEW=2）：`90-104 40.0% / 105-119 17.1% / 120-134 12.9% / 135-149 10.9% / 150-164 9.8% / 165-180 9.2%`，均值 120.2，min 90 / max 180，**两道 ≥55 只占 3.4%**。

- 按**出身**给主/次道（权重 3 / 1.8 / 0.5），每道先给 2~6 点底，避免一排 0。
- 余量按权重随机加，单道封顶 60；再把每道拆成 6 个天赋项（每项 ≤60）。
- 与境界**无关**：180 点的凡人仍是炼气 1~3 层（潜力 ≠ 修为）。
- 区间仍是硬约束 `[90,180]`（`checkCandidate` 断言），偏斜只改**密度**不改边界；想调形状只动 `CFG.TALENT_SKEW`，前端 `crew-model.CFG.TALENT_SKEW` 要同步。

## 五、特质

**只发正面。** 负面特质（懒散 / 愚钝 / 孤僻 / 嗜睡 / 急躁 / 大胃 / 笨拙 / 畏战 / 走神 / 亏血 / 怯懦）**一律不再生成** —— 招募池是给人挑的，谁都不想抽到一个全是缺点的弟子。

- 条数 `rint(1,3)`，从 24 条正面特质里抽，**同名不重复**。
- 同一 `k` 互斥（`pair = 'solo-' + k`），过桥时不会误判成"正反同现"。

### 5.1 抽取方式：量化加成 → 权重 → 累计和轮盘

**不再「先掷档、再抽条目」**。那样档位概率是常数，3 条独立掷，`epic` 会叠加到 9% 的人有天命 —— 就是"人均天生道体"的来源。

现在分三步：

1. **每条特质给一个 `bonus`（1~10）** —— 加成的量化强度，不是稀有度标签。它是游戏内真实强度的排序，也是抽取权重的唯一输入。
2. **权重 = `TRAIT_W_BASE / bonus^TRAIT_W_EXP × TRAIT_TIER_MULT[tier]`**
   `bonus=2 → 17.7 · 4 → 3.1 · 7 → 0.76 · 10 → 0.316`（epic 再 ×0.3）⇒ 天生道体比辟谷难出 **约 380 倍**。
3. **把候选权重累加成一条数轴，`x = rng() * 总权重`，从头往下扣，扣穿谁就是谁**（权重轮盘）。

另外两道闸，防止"一条命顶三条"：

| 闸 | 值 | 作用 |
|---|---|---|
| `TRAIT_HIGH_CAP` | 1 | 每人 rare+epic 合计**最多 1 条**（三条神体不可能） |
| `TRAIT_BONUS_CAP` | 10 | 单人加成合计上限；抽走高档后预算见底，只能配低档或提前收手 |

### 5.2 特质表（`bonus` 即权重输入）

| 档 | bonus | 特质 |
|---|---|---|
| 寻常 common | 2~3 | 辟谷 2、勤勉 2、夜行 2、巧手 2、专注 2、胆识 2、坚毅 3、血旺 3 |
| 良 uncommon | 3~4 | 亲和 3、耳目清明 3、妙手回春 3、心如止水 3、慧根 4、沉静 4、过目不忘 4、铜皮铁骨 4 |
| 异禀 rare | 5~7 | 天生灵眸 5、福缘深厚 5、五行亲和 5、**天生魅体 6**、力大无穷 6、龙象之力 7 |
| 天命 epic | 9~10 | 道心通明 9、天生道体 10 |

### 5.3 实测（10 万人）

| 指标 | 数值 | 换算 |
|---|---|---|
| 至少一条天命 epic | **0.15%** | 约 1/660 人 |
| 天生道体 | **0.07%** | 约 1/1430 人 |
| 天生魅体 | 0.84% | 约 1/119 人 |
| 至少一条异禀 rare+ | 6.3% | 约 1/16 人 |
| 档位占比（按条） | common 75.2% / uncommon 21.6% / rare 3.2% / epic 0.08% | |
| 单人加成合计 | 均值 **4.96**，最大 10（上限卡死） | 三条全高不可能 |

> 调参就三处：想更苦 → `TRAIT_W_EXP` 调大（如 3.0）；想让天命更稀 → `TRAIT_TIER_MULT.epic` 调小（如 0.2）；想让每人只出一条高档 → `TRAIT_HIGH_CAP` 保持 1。
> ⚠ 前端 `crew-model` 有同一套常量（`TRAIT_W_BASE/EXP/TIER_MULT/HIGH_CAP/BONUS_CAP`），**改一边必改另一边**，否则招募池和面板演示数据两套手感。

### 5.4 百分比口径：一律「原值 ÷4」

特质文案里的百分比**全部是原始数值的四分之一**（2026-11-25 定案）。原来动辄 +20% / +35% / +50%，一个特质顶别人半套装备，数值空间被吃光。

- **百分比** ⇒ 除以 4，四舍五入：`+50% → +13%`、`+35% → +9%`、`+20% → +5%`、`+10% → +3%`、`-30% → -8%`。
- **点数值不缩**：`气血上限 +10`、`同门心境 +8`、`神识范围 +1 格` 是绝对量，本来就小，照旧。
- 落在派生值上时**保底 1 点**：`def 19 × 5% = 0.95` 取 1，否则 `Math.round` 会把它抹成 0、等于没生效。

### 5.5 已落地到数值的（`crew-model.attrs()`）

| 特质 | 效果（缩水后） |
|---|---|
| 血旺 | 气血 +4% |
| 坚毅 | 气血 +10（点） |
| 胆识 | 攻击 +3% |
| 龙象之力 | 气血 +6%、攻击 +4% |
| 力大无穷 | 攻击 +5% |
| 铜皮铁骨 | 防御 +5% |
| 耳目清明 | 命中 +8（点）、闪避 +2% |

实测（同一角色换特质，`hp 126 / atk 22 / def 19 / dodge 12` 为基线）：

| 特质 | 变化 |
|---|---|
| 血旺 | hp 131（+5） |
| 胆识 | atk 23（+1） |
| 龙象之力 | hp 134、atk 23 |
| 铜皮铁骨 | def 20（+1） |
| 耳目清明 | hit 65（+8）、dodge 13（+1） |

其余（修炼速度 / 突破率 / 炼器成器 / 心境 / 聚气 / 奇遇）**还没有对应的派生字段**，等属性层补齐 —— 面板上只显示文案，不显示数值差。
⚠ `crew-model.TRAIT_PAIRS` 里的负面条目只作**旧档兼容**保留（`attrs()` 仍有 `亏血/畏战/怯懦` 分支，同样按 1/4 缩成 `×0.96 / ×0.96 / -2`），不再有任何生成路径会产出它们。

## 七、境界 / 修为

- `realm = '炼气期 · N 层'`，`N ∈ {1,2,3}`。
- 炼气段上限取 `EXP_STAGE_MAX = 600`（**不是** `600 + total*6`；后者会让 180 天赋的炼气凡人修为条直接顶到筑基门口）。
- `exp = round(EXP_STAGE_MAX × rint(5,60)/100)`，保证 `> 0`。
- ⚠ 现有 `expOf()` 仍用 `600 + total*6`；接入时要么改 `expOf`，要么在本生成器里另带 `expMax` 字段。**这是待办，不是已完成。**

## 八、神通 / 装备

**神通**：`arts = { slots: [], cap: 3, from: '未习' }`。靠功法书 + 闭关时间获得，生成器一律不给。

**装备**：只给"起步件"（粗布道袍 / 束发巾 / 桃木剑 / 铜铃），保证角色不是裸的；
法宝 1 件起（队列 1，满足 1~4）。品阶不设门槛 —— 等"灵力驱动"规则落地后，由装备侧校验
`Σ 装备驱动的灵力需求 ≤ 角色灵力上限`；该字段（建议 `mpNeed`）**尚未存在**。

## 九、种子（可复现 + 不可重 roll）

```
seed = fnv1a([worldSeed, settleId, round, slot, salt].join('\u0001'))
rng  = mulberry32(seed)
```

- 同 `(worldSeed, settleId, round, slot)` ⇒ 逐字段一致，多端/刷新都可复现。
- `slot` 是候选人在池子里的下标；**招走的人占位，不重排**（否则返回面板会换人）。
- 世界种子是服务端资产，本生成器只**消费**，不产生。

## 十二、验收

1. `node` 载入：`global.window = globalThis; require('.../Engine/js/chargen.js')`。
2. `Chargen.selfTest()` 必须 `ok:true`，1000 个样本零错误。
3. `stats(100000)`：五年限分布各档与 §3.1 相差 **≤ 0.4pp**（1% 档允许更宽，样本足够时按比例判，**不用绝对值**）。
4. 同参数调两次，`JSON.stringify` 完全相同（确定性）。
5. 边界：`slot` 0~8、`opts.gear=false`、`k=1`、`k=5` 都不许抛。
