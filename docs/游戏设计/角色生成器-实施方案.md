# 角色生成器 · 实施方案（可招募弟子）

> 日期 2026-11-25 ｜ 状态：**生成器已落盘，尚未接入 UI / 服务端**
> 真源代码：`Server/Zongmen/Engine/js/chargen.js`（出口 `window.Chargen`）

---

## 一、这份文档解决什么

开局要在**地图上的聚落**随机招人。需要一个**确定性、可复现、纯函数**的弟子生成器，产出的对象直接能被
`web/js/crew/` 那一套（`CrewBridge.validate/hydrate` → `CrewModel.attrs` → `CrewPanel`）接受。

**不做**的事：不算派生值（气血/攻防/命中都现算）、不落库、不管 UI、不管定价与名额。

### 三个生成器别混

| 名字 | 位置 | 用途 | 口径 |
|---|---|---|---|
| `CrewModel.demoSquad` | `web/js/crew/crew-model.js` | 前端演示数据（6 人 + 48 格背包） | 六道 + 灵根，**境界由天赋推** |
| `CultivatorGen` | `Subsystems/Characters/js/chargen-core.js` | 世界人口（地图热力图 / 名录 NPC） | 数据驱动、正态分布、**另一套字段** |
| **`Chargen`** | `Engine/js/chargen.js` | **玩家可招募弟子** | 本档口径，产 `crew` 契约形状 |

三者互不调用。将来若合并，以 `Chargen` 的字段为准，另两处各写适配层。

| 来源 | 内容 |
|---|---|
| `docs/游戏设计/角色系统设定表.md` | 弟子 = 灵根 + 天赋 + 特质 + 装备 + 神通 |

| 用户 2026-11-25 | ① 天赋 **90~180 均匀**，不做聚落分级（后期升级加得更多）② **只生成凡人（炼气）** ③ 灵根**合计 100**，与觅长生同构；玩家侧**至少一系，最低 20**，系数量按 1/2/3/4/5 = **1%/2.5%/20%/30%/46.5%** ④ 装备不设品阶门槛，走「灵力驱动」⑤ 神通靠修炼时间，开局没有 |

### 硬约束（生成器必须满足，`selfTest()` 逐条断言）

| 项 | 约束 |
|---|---|
| 灵根 | 五项之和 **恒 = 100**；每项 ∈ {0} ∪ [20,80]；非零项数 = 抽到的 `k` |
| 天赋 | 总量 ∈ [90,180]，六道之和 = 总量，**单道 ≤60**，每道 6 项**单项 ≤60** |
| 特质 | 1~3 条，同 `pair` 正反不共存 |
| 装备 | 5 槽类型必须与物品 `kind` 一致；法宝队列 1~4 |
| 神通 | 已学 `slots` = **0**，格数 `cap` = 3 |
| 境界 | 恒为 `炼气期 · 1~3 层` |
| 修为 | `exp > 0` 且 ≤ 炼气段上限（见 §七） |

## 三、灵根

### 3.1 系数量分布

| k | 概率 | `rng()` 累计阈值 | 读法 |
|---|---|---|---|
| 1 | 1% | `x < 0.010` | 天灵根（单系 100） |
| 2 | 2.5% | `x < 0.035` | 双灵根 |
| 3 | 20% | `x < 0.235` | 三灵根 |
| 4 | 30% | `x < 0.535` | 四灵根 |
| 5 | 46.5% | 其余 | 杂灵根（20×5） |

### 3.2 分配算法（整数、必然 100）

1. 抽 `k` → 从金木水火土里随机挑 `k` 个（**若给了本地灵脉五行，主系优先落该系**，其余随机）。
2. 这 `k` 个系先各给 **20 点**（k×20 是底）。
3. 余数 `R = 100 - 20k`（k=1→40 / 2→60 / 3→40 / 4→20 / 5→0），按权重切给这 `k` 个系：
   **主系权重 3、其余各 1**；整数随机切分，每份 ≥0，总和 = R。
4. `main` = 值最大的下标（并列时随机取一个，**不许固定 0**）。

### 3.3 典型结果（权重 3:1）

| k | 例 | 含义 |
|---|---|---|
| 1 | 100/0/0/0/0 | 天灵根 |
| 2 | 65/35 | 主次分明 |
| 3 | 44/28/28 | 三灵根 |
| 4 | 30/23/23/24 | 近杂 |
| 5 | 20×5 | 杂灵根（最常见） |

> ⚠ **0 值的语义**：该系永久不通 —— 不能聚这系灵气、不能学这系神通。**"无灵根"（五项全 0）在玩家侧不存在**；
> 若以后要出「无灵根凡人杂役 / 敌修」，必须另加标记，否则 `CrewBridge` 的 `sum≤0 → [20,20,20,20,20]` 兜底会把它们变成五灵根。

## 四、天赋

- 总量 `total = rint(90,180)`，**均匀**。
- 按**出身**给主/次道（权重 3 / 1.8 / 0.5），每道先给 2~6 点底，避免一排 0。
- 余量按权重随机加，单道封顶 60；再把每道拆成 6 个天赋项（每项 ≤60）。
- 与境界**无关**：180 点的凡人仍是炼气 1~3 层（潜力 ≠ 修为）。

---

## 五、特质

- 条数 `rint(1,3)`，从 11 组 `pair` 里不重复抽，每组按 55% 取正 / 45% 取负。
- ≥2 条时强制**至少一正一负**（沿用现有口径）。
- ⚠ 现有 `attrs()` 只认 6 条（血旺/亏血、胆识/畏战、坚毅/怯懦），`rateOf()` 只认 2 条（勤勉/懒散）；
  **22 条里 14 条目前不产生任何效果**。生成器照发（数据是完整的），效果等属性层补。

| 出身 | 天赋偏置（主/次） | 备注 |
|---|---|---|
| 农户 | 气 / 体 | 最常见 |
| 猎户 | 体 / 器 | |
| 渔家 | 气 / 阵 | 靠水 |
| 铁匠 | 器 / 体 | |
| 游医 | 丹 / 气 | |
| 流民 | 体 / 气 | 心境偏低 |
| 落第书生 | 神 / 阵 | |

入宗后再转职司（现有 `ROLES` 那 7 种），本生成器不决定。

## 七、境界 / 修为

- `realm = '炼气期 · N 层'`，`N ∈ {1,2,3}`。
- 炼气段上限取 `EXP_STAGE_MAX = 600`（**不是** `600 + total*6`；后者会让 180 天赋的炼气凡人修为条直接顶到筑基门口）。
- `exp = round(EXP_STAGE_MAX × rint(5,60)/100)`，保证 `> 0`。
- ⚠ 现有 `expOf()` 仍用 `600 + total*6`；接入时要么改 `expOf`，要么在本生成器里另带 `expMax` 字段。**这是待办，不是已完成。**

## 八、神通 / 装备

**神通**：`arts = { slots: [], cap: 3, from: '未习' }`。靠功法书 + 闭关时间获得，生成器一律不给。

**装备**：只给"起步件"（粗布道袍 / 束发巾 / 桃木剑 / 铜铃），保证角色不是裸的；
法宝 1 件起（队列 1，满足 1~4）。品阶不设门槛 —— 等"灵力驱动"规则落地后，由装备侧校验
`Σ 装备驱动的灵力需求 ≤ 角色灵力上限`；该字段（建议 `mpNeed`）**尚未存在**。

## 九、种子（可复现 + 不可重 roll）

```
seed = fnv1a([worldSeed, settleId, round, slot, salt].join('\u0001'))
rng  = mulberry32(seed)
```

- 同 `(worldSeed, settleId, round, slot)` ⇒ 逐字段一致，多端/刷新都可复现。
- `slot` 是候选人在池子里的下标；**招走的人占位，不重排**（否则返回面板会换人）。
- 世界种子是服务端资产，本生成器只**消费**，不产生。

    queue: ['srv-c-…-talisman'], queueFrom: '本命一件',

| 名字 | 说明 |

## 十二、验收

1. `node` 载入：`global.window = globalThis; require('.../Engine/js/chargen.js')`。
2. `Chargen.selfTest()` 必须 `ok:true`，1000 个样本零错误。
3. `stats(100000)`：五年限分布各档与 §3.1 相差 **≤ 0.4pp**（1% 档允许更宽，样本足够时按比例判，**不用绝对值**）。
4. 同参数调两次，`JSON.stringify` 完全相同（确定性）。
5. 边界：`slot` 0~8、`opts.gear=false`、`k=1`、`k=5` 都不许抛。
6. 过桥：`CrewBridge.hydrate(contract)` 的 `errors` 必须为空（**warnings 允许**：法宝 0 件、activity 缺失之类由上层补）。

### 12.1 本次实测（2026-11-25，Node 22）

| 项 | 结果 |
|---|---|
| `selfTest(3000)` | `ok:true`，0 错误，约 210ms |
| `stats(50000)` | `bad:0`；天赋均值 135、min 90、max 180 |
| 灵根系数量 | 1 系 **0.95%** / 2 系 **2.50%** / 3 系 **20.12%** / 4 系 **29.85%** / 5 系 **46.58%** |
| 池子（town / pop 420） | 6 人；同参数两次 `JSON.stringify` 完全一致 |
| `CrewBridge.hydrate` | `ok:true`，**errors 0**；warnings 只有「神通 0 格」 |
| `CrewModel.probe` | **6 条 violations，全是「神通格 0」** ← 已知断言冲突（见 §14 #2），接入前必须改 |

派生值链路是通的：一个人 `hp 80/100 · mp 48/72 · atk 18 · def 12 · hit 62 · dodge 10 · 负重 11/87`。

## 十三、接入方式（本次**未做**）

`chargen.js` 目前**不在任何 bundle 里**，属于「落盘但未接线」。接线要动三处：

1. 服务端 bundle 数组加 `chargen.js`（`JsvmModule.BuildBundle`）；若要按 seed 走世界层出口，还要在 `WorldModule.Invoke` 的 switch 加 case。
2. `ComputeEngineHash` / `EngineScriptOrder` **建议不纳入** —— 它不是地图引擎的一部分，纳入后每次改生成器都要清世界库。
3. 前端预览 / 判据：`global.window = globalThis` 后直接 `require` 或 `<script src>`，无依赖。

> ⚠ 改 bundle 必须重启服务端；载荷若变还要停服清 `db/zongmen.sqlite*`。
> 只想先看效果的话不必接线 —— 用 Node 跑本文件即可。
