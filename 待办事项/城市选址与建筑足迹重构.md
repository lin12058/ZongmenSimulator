## 二、道路寻路：A* → 带权重 BFS

现状：`roadCost` 数组按 biome 取代价，`astar` 取每条可行路。
改为 **BFS + 地形权重 + 双向剪枝**：

### 权重表

| 地貌 | biome | 权重 |
|------|-------|------|
| 水（深海/浅海/沙滩） | deep/ocean/beach | **4** |
| 平地（草地/沙漠） | grass/desert | **3** |
| 森林 | forest | **5** |
| 山地（山/雪峰） | mountain/snow | **8** |

### 剪枝上限（**已拍板：120 权重 / 40 步**）

- **累计权重上限 120**：任一候选累计 cost ≥ 120 停止扩展该分支。
- **步数上限 40 格**：六边形 BFS 第 40 层未命中即放弃。
- 口径 = 「等价平地格数 × 平地权重(3)」：120 权重 ≈ 40 格平地，与 §四 贸易 `reachableBudget≤40格` 同口径。
- **定值依据（实测，灵域半径 ≈ 577 格）**：最近邻聚落对 `hexDist` 中位 11~12 格 / p90=23 / max 61；
  文档原值 30 权重（≈10 格）实测**建路率仅 24.8%**（砍掉约 3/4 既有路网，A\* 基线 91.4%），不可接受；
  改 120/40 后建路率恢复 **89~92%**，且最慢单 region 由 A\* 时代 ~540ms 降至 **53ms**（典型 22ms）。
- 双重剪枝保证道路只在**城镇周边邻域**内连通，不会像 A* 跨大陆找路（A\*=60000 上限导致海岸破碎区秒级卡死病灶也一并消除）。

### 改动点

- `mapgen.js`：已删除 `astar` / `Heap` / `roadCost`，新增 `bfsRoad` / `roadWeight` / `roadMinWeight`（权重表在 config 的 `ROAD_W`）。
- **三重剪枝**：权重剪枝（`ng+h > ROAD_COST_MAX`）、步数剪枝（`ds > STEPS_MAX`）、
  下界剪枝（`g+minW*dn > COST_MAX`）+ 步数透镜（`ds+dn > maxSteps`）；均为可采纳剪枝，不改最优解。
- **桶序 = `f = g + h`**（等价 A\* 展开序，收敛快于按 `g` 分层）；桶内 FIFO + `NEIGH_SLOTS` 固定序 → 确定性。
- 失败对仍记入 `roadFail`，终身跳过。
- `verify/w3_astar_budget.mjs` → 已由 **`verify/w3_bfs_road.mjs`** 取代（7 项断言：权重表契约 / 双预算上界 /
  权重累加自洽 / 邻域剪枝全量 null / 下界剪枝不改路径（与无剪枝参照逐对一致）/ 确定性（重复+跨实例）/
  端到端建路率≥70% + 最慢单 region<250ms）。
- `roadVer` / `roadCache` / `roadsNear` 语义不变（roadCache 每新增一条路 +1）。

## 三、城镇生成：勘测 → 选址 → 生长

三段式流水线，取代 `settlementsFor` 的直接落点。

### 阶段一 勘测（Prospect）

```
锚点 = settlementsFor(i,j) 原落点
以锚点为中心六边形 bfs 扩展 R = PROSPECT_R (=4; 文档原建议 6, 实测代价按格数平方增长 → 取 4)
采样区内每格: biome / elev / veinNear / 灵脉浓度 / 邻地貌
→ 生成「适宜度图」(siteScore 基础分)
资源邻近只对基础分前 PROSPECT_REFINE(=6) 名精算 (TERR_SCAN_R=1) —— 精算是主要开销
```

> ⚠ 曾试过「按环提前收敛」(PROSPECT_ACCEPT) 以求性能，实测**改变 37.8% 城镇中心** → 已撤销。
> 中心质量优先：严格取最高分格，不做有损收敛。

### 阶段二 选址（Pick Center）

对勘测区内每格打分 `siteScore(tile)`：

| 打分项 | 逻辑 | 权重示意 |
|--------|------|----------|
| 地形宜居 | 草地最优，森林次优，沙漠/山地折价，海洋/雪峰排除 | 80/60/30/20/-∞ |
| 海拔适中 | 0.45~0.75 最优，偏离线性衰减 | 峰值100 |
| 资源邻近 | 扫描半径内农田/矿脉/森林/水源格加成 | 依据资源密度 |
| 灵气加成 | veinNear d=0 最高，d≤1 次之 | 60/30 |

取**最高分格**为城镇真实中心（保证周边确实有「好空间」）。

### 阶段三 生长（Building Propagation）

以选定中心为锚，`hexDist ≤ TOWN_R(=3)` 填充（含中心共 37 格候选）：

```
1. 中心格 → 城镇核心建筑 (按 type: 村口/祠堂/宗祠/山门)
2. 遍历 37 格 → 灵气×地形 → 地皮类型 → 建筑候选池
3. 空间分工: 内环(TOWN_INNER_R=1) 铺民居/仓库 (城区), 外环铺生产型卫星
4. 生产型卫星先行 (码头/农田/矿场/林场…), 民居按 TOWN_HOUSE_RATIO=0.3 保底配额
5. 产出聚合 → 城镇资源清单 (ResourceQuant[])
6. 建筑数上限按规模分档: TOWN_BUILD_MAX {village:8, town:16, city:25, sect:16}
```

> 教训: 良田判定过宽时曾出现 **98.6% 都是农田、民居仅 1.4%**。改为「中心核心 → 内环民居 → 外环生产卫星」
> 的空间分工 + 民居保底配额后，民居占比回升到 **23.8%**。

### 灵气 → 地皮 → 建筑映射

```
灵脉中心(d=0)      → 灵枢地皮   → 祭坛/灵枢殿/聚灵阵
灵脉从属(d≤1)     → 高阶灵地   → 炼丹/炼器殿
元素=水 & 沿海      → 水岸地皮   → 码头/渔船坞/渔亭
元素=木 & 森林      → 林地皮     → 伐木场/药圃
元素=金 & 山地      → 矿脉地皮   → 矿山/熔炉
元素=火 & 沙漠      → 灼壤地皮   → 炼炉/焦炭窑
元素=土 & 草地      → 良田皮     → 农田/磨坊/谷仓
低灵 & 平地          → 村落皮     → 民房/仓库
产出聚合：每建筑 → 资源量 → 城镇 ResourceQuant
```
