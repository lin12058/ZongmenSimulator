## 二、b 方案（已实现）

### 2.1 一句话

**骨架建筑逐字节不变（seed 纯函数），变的是「哪几座被点亮」+「骨架之外新盖了什么」+「每座几级」** ——
三者都是 `(pop, tier, state, type, 骨架产出)` 的**纯函数**，不落库、不进 `townCache`、不参与 `townNet`。

### 2.2 为什么必须「纯派生」

- **红线 R1/R2 不破**：`growTownFootprint` 一行未改，`townCache`/`townNet`/`tradeCache` 的失效条件不变。
- **Δ 铁律天然成立**：末态建筑集 = 末态人口的函数，与 dt 拆分路径无关
  （实测 `step(s,360) ≡ 12×step(s,30)`，Δ pop = 0、Δ built = 0）。
  旧版「余数累加器」在人口回退时会留下**幽灵建筑**，已废弃。
- **不重排坐标**：格位由 seed 定死；若按 pop 重排，删一座会级联改其余位置（v2 §1.3 的硬结论）。

### 2.3 模型

```
骨架 maxN = CFG.TOWN_BUILD_MAX[type]        (city 25 / town 16 / village 8 …)
标准人口 ref = E.BLDG_POP_REF[tier]         (1:3000 / 2:15000 / 3:50000)
ratio = pop / ref

目标建筑数 cap = round(maxN × ratio^0.6)     ← 次线性：大城不会无限膨胀
  上限 = maxN × (1 + BLDG_CAP_OVER=1.0)
  下限 = BLDG_CAP_MIN = 1
  state=3(灾荒/战乱) ⇒ cap = floor(cap × FAMINE_CAP=0.65)
  state=1(被毁)      ⇒ cap = 0

点亮集合 = 骨架按优先级排序后取前 min(cap, 骨架数)
优先级 = 组(0 核心 → 1 城区民居 → 2 生产卫星) → 离城心距离 → (q,r)
   ⇒ 人口萎缩时**外圈先消失**，中心最后

溢出建筑 = cap − 骨架数 (>0 时)
  放在骨架环 (TOWN_R) 之外的若干环上 (确定性 hash 选格, 避开灵脉/深海)
  1/3 为生产建筑 (优先补最紧缺资源), 其余民房/仓库

等级 lv ∈ [1,3]:
  核心建筑   lv = 城 tier
  民房/渔家  lv = 1 + floor(ratio / LV_HOUSE_STEP)
  生产建筑   lv = 1 + (紧缺度≥0.25) + (紧缺度≥0.60)      ← 「按作用调整」
```

### 2.4 数据流（闭环已通）

```
TickPump → TickVmPoolExecutor.EvolveOne
   → cityMetaJson(type,q,r)        ← 身份往返（本次修复）
   → cityEvolveJson(state, meta, dt)
        内部 built[] = planOverflowOnly(meta, {pop,tier,state})   ← 纯派生
   → PersistRow → CityStateStore.Put
   → MarkSettleDirty(i,j)          ← EvictWithGate + BumpBlockRev(Settle|Poi)
                                     （否则客户端永远看到初始建筑，不报错）

客户端拉块 → GetTileBlock → SettlePackOf → GetSettleBytes → BuildSettle
   → SettleOverlayJson(i,j)        ← 从 CityStateStore 取**本区域格**的 {pop,tier,state}
   → citySettlePlanJson(i,j,overlay)
        骨架 ⊕ 计划 ⇒ towns[].buildings[{q,r,kind,terrain,tier,lv}]
   → SettlePack(protobuf, gzip) → 前端 spriteOf(lv) → 楼/规模
```

## 四、事件接口（后续打仗/天灾的接入点）

```csharp
// 唯一写入口。事件层只调它，不直接改 Pop/PopF。
CityStateStore.ApplyShock(int round, string id, int deltaPop, int? newState)
//   deltaPop : 人口增减（可负，战损/瘟疫）；结果夹到 >= 1
//   newState : null=不改；1=被毁（建筑全灭）；3=事件态（建筑折减，持续到恢复）
```

- **刻意不动 `PopBase`**：事件态判据 `pop < PopBase×0.7`、恢复判据 `×0.9` 都相对它
  ⇒ `state=3` 会「持续到真正恢复」，而不是下一 tick 就解除。
- 施加后 `Ver += 1`（客户端缓存失效）；`PopF` 同步（否则下一批从旧浮点续跑）。
- 尚未做：**事件持久化表**（战役/灾害排程）与 HTTP 触发口 —— 待用户定义事件规则后接。
