## 1. 需求逐条拆解

### R1 + R2：大灵脉「1 中心 + 6 低峰」、中灵脉「1 中心 + 左下/右下」

**现状（为什么没有）**

| 位置 | 事实 |
|------|------|
| `mapgen.js:117-119` | `veinFootKeep(level,dq,dr)` **恒 `return dq===0 && dr===0`** —— 三档灵脉一律只占本格。注释明写「早先按等级铺 7/3/1 格，密排后连成一片尖顶山簇，实机读作三角形山」故于六版砍掉。 |
| `mapgen.js:369-374` | `fields()` 只在 `vn.d<=1 && e>=SEA_LEVEL` 且 `veinFootKeep(...)` 通过时写 `vinfo`。占地恒本格 ⇒ **只有中心格带 vein 信息**。 |
| `mapgen.js:286-298` | 海拔上其实**已经**有七星动作：`vn.d===0` 抬到 `LIFT_CORE[level]`；`vn.d===1` 抬到 `coreE - LIFT_ARM_OFF(0.05)`；d=2/3 递减过渡。⇒ 6 个邻格被抬成山，**但前端不把它当灵脉**（无 vein 标记 → 画普通山/树）。 |
| `main.js:1604` | 详情面板文案仍是「大灵脉·七星 / 中灵脉·七星 / 独立小灵脉」—— **文案与实现已经不一致**（用户看到的"七星没了"正是这个）。 |

**目标**（用户原话口径）

- 大灵脉：中心 1 格 + **六邻 6 格**，6 格**明显低于中心**；
- 中灵脉：中心 1 格 + **左下（西南槽 2 = `(-1,+1)`）+ 右下（东南槽 1 = `(0,+1)`）各 1 格**，低于中心；
- 小灵脉：**无从属**（仍 1 格）。

槽位口径 = `mapgen.js:109 NEIGH_SLOTS`（0东 1东南 2西南 3西 4西北 5东北；世界坐标 `x=hexW*(q+r/2), y=1.5*hexR*r`）。左下 = 西南 = `(-1,+1)`，右下 = 东南 = `(0,+1)`。

**改法（用户已拍板 D1=B：专用「从属」第 4 档；下表步骤 1/4 不变，步骤 2/3 按四档口径改写）**

| 步骤 | 文件 | 动作 |
|------|------|------|
| 1 | `mapgen.js:117` | `veinFootKeep(level,dq,dr)` 改为按档占地：level 0 → `hexDist(0,0,dq,dr) <= 1`（7 格）；level 1 → 本格 + `(-1,1)` + `(0,1)`（3 格）；level 2 → 本格（1 格）。纯函数不变（只依赖 level 与偏移）。 |
| 2 | `mapgen.js:369-374` | `vinfo` 的 level：中心格 `level: vn.v.level`；从属格 **`level: 3`（D1 的专用第 4 档，不参与 0/1/2 语义）**。其余字段（element/variant/name/d）不变。 |
| 3 | 全自动 | `buildChunk` 的 `propElevs[i] = f.vein.level`（`mapgen.js:415` 一带）→ 从属格自动拿第 4 档高度；复合通道改 **`(等级 + 海拔)/4`**（D1），max = `(3+1)/4 = 1.0`，**不溢出**；`renderer.js` 自动画出比小灵脉更矮的从属峰 + 同款底座。 |
| 4 | 禁用项核查 | 灵脉名牌只在 `commCells[].veins[]` 上出（`main.js:1208-1214`），从属格**不在** veins 列表 ⇒ 不会多出 6 个名牌；`veinNear` 的 d≤3 地形过渡/生态偏置不变。 |

**副作用（必须承认）**

- 群落区域的「山峰格数」大幅上升：一个大灵脉从 1 格变 7 格（+600%），一个中灵脉 1 → 3 格。
- 从属格仍可能被画成**带底座的低档峰**，视觉上仍是"一片峰"，只是高度有层次（从属档高 < 小灵脉）。R1 用户要的就是这个；但**若实机仍读作"山簇"**，退路是收 `sizeScale` 或只画 3 格从属（保留"七星"的名，不铺满 6 格）。
- 从属格会同时被 R4 列入禁建（必然）。

**B 方案（✅ 已采纳，D1）**：`vein-skin.js` 新增第 4 档「从属」（如 `hScale 1.05 / hRand [0.70,0.86]`）。代价：`levels` 由 3 → 4、`check_vein_skin` 契约重写、`renderer.js` 的 `iElev` 复合通道**除数 3 → 4**（`main.js:960` 与 shader `*4.0`、`min(floor(vz),3.0)` 同步），触及九版 u16 打包契约，需重跑探针。**收益**：从属峰与"独立中/小灵脉"不再同高，语义清晰。**落地清单见 §9「D1 契约改造」。**

**验收**：新增 `verify/check_vein_cluster.mjs`（引擎侧）——扫 N 个群落断言：大灵脉六邻皆从属且 `level = 中心+1`；中灵脉恰有 `(-1,1)`、`(0,1)` 两个从属；小灵脉无从属；从属格 `fields().vein` 存在。`check_vein_skin.mjs:141-155` 的「占地 = 仅本格」三条断言改写为 7/3/1。

### R3：小灵脉高度偏低

**§2.1 先看根因（建议优先修这个，而不是直接抬 hScale）**

九版给灵脉加「山地底座」时，底座高度倍率走的是**与大世界山同一档公式**（`renderer.js:206-207`）：

```
if (ve > 0.84)      bhs = mix(0.95, 1.55, (ve-0.84)/0.12)   // 雪峰档
else if (ve > 0.70) bhs = mix(0.55, 1.30, (ve-0.70)/0.14)   // 山地档
```

而灵脉中心格海拔被抬到 `LIFT_CORE = [0.80, 0.75, 0.70]`（`mapgen-config.js:43`）：

| 档 | 中心海拔 | 底座 bhs | 底座上屏高 ≈ `(3.3+1.2h)*bhs` | 峰体上屏高（×sizeScale 0.40） | 合计 ≈ |
|----|---------|---------|------------------|------------------|--------|
| 大 | 0.80 | ≈1.086 | ≈4.2 uR | 3.16~3.42 | **≈7.5 uR** |
| 中 | 0.75 | ≈0.818 | ≈3.2 uR | 2.74~2.84 | **≈6.0 uR** |
| 小 | **0.70** | **0**（严格 `> 0.70` 不成立） | **0** | 2.03~2.17 | **≈2.1 uR** |

⇒ **小灵脉只有大灵脉的 ~28% 高**，且完全没有山脚（峰体直接"插"在地面上）。判定阈值是严格大于，而 0.70 恰好落在边界上；再加上 `(等级+海拔)/3` 经 **u16 量化**（`main.js:960` → `renderer.js:196-199` 还原），实际值会是 0.6999… 或 0.7000…，**结果不稳定**。

同款严格大于也存在于 `main.js:874`（`veinTopU`，名牌锚点）与大世界地形分支（`renderer.js:213`），但**只有小灵脉会被卡在边界上**。

**改法（建议叠加）**

| 编号 | 改法 | 位置 | 效果 | 代价 |
|------|------|------|------|------|
| R3-a（首选） | 新增 `SHAPE.terrainBaseMin`（默认 0.30），PROP_VS 灵脉分支取 `bhs = max(bhs, TB_MIN)`；`veinTopU` 同步 | `vein-skin.js:77` 附近 + `renderer.js:208` + `main.js:875` | 小灵脉也有 ≈1.3 uR 山脚，三档层次连续；不动大世界山 | 需同步 `check_vein_skin.mjs` 契约与 `tools/prop_sheet.mjs` |
| R3-b | `LEVELS[2].hScale: 1.22 → 1.45`、`hRand: [0.72,0.96] → [0.82,1.00]` | `vein-skin.js:131` | 小档上屏 2.03~2.17 → **2.48~2.61 uR（+20%）**；相对高度 6.21~6.53 仍 < 中档下界 6.84 ⇒ 三档不重叠断言仍成立 | 小档单独立项提升的余量上限就在这（再高就撞中档，见下） |
| R3-c | `LIFT_CORE[2]: 0.70 → 0.745` | `mapgen-config.js:43` | 直接给小灵脉底座（bhs ≈ 0.77） | **改地形**：灵脉中心更高、`siteScore` 海拔项/生态都跟着动；且落入"浮点边界"风险区，需实测 |

**更大提升的天花板**：小档要让位给中档（中 min = 6.84）。若目标是小灵脉上屏 ≈3.0 uR（≈现在中档），就必须**整体重排**（中 1.58→1.80、大 1.90→2.05…），会顶破 `check_vein_skin` 的「大档上屏高 ≤ 3.6 uR」断言（`check_vein_skin.mjs:27-28`），需同步放宽断言或下调 `sizeScale`。**→ 已拍板 D2=b：不做整体重排、不改 `LIFT_CORE`；只采纳 R3-a（底座下限）+ R3-b（hScale 1.22→1.45）。**

**验收**：`check_vein_skin.mjs` 增断言「小档底座不为 0（沿用 R3-a 时）」；前端探针量「同底同刻度看板」下小灵脉可见高度（`tools/prop_sheet.mjs`，别用固定屏幕窗口/RGB 阈值）。

| `main.js:1024-1037` | 建筑已带 `st`（聚落实体，`id = i_j_k`、`type`、`name`）⇒ **城镇身份信息前端已有**，无需改协议。 |
| ⚠ `bldg_ink.js:1790-1792` | `spriteOf` 的缓存 key = `kind|dir|variant|R|detail|tier|water`，**不含 tint** ⇒ 直接把城镇色塞进 `tint` 会**串色**（第一个城镇的颜色被所有城镇复用）。而直接把 tint 加进 key，`SPR_CAP=512` 会被"城镇数 × 地皮数"撑爆。 |

**改法（推荐：把地盘从精灵缓存里拆出来）**

1. `bldg_ink.js` 新增轻量出口 `plateAt(ctx, {cx, cy, R, tint, a, edge})`（内部就是 `hexPts` + 填充 + 墨边 + 柔光），**不进 `_spr` 缓存**；`main.js` 在贴建筑精灵**之前**逐格现画地盘（设备像素坐标系，与现有 `ctx.setTransform(1,0,0,1,0,0)` 段一致）。
2. `main.js` 新增 `townColor(st)`：由 `st.id` + `st.type` 派生**确定性 HSL**（同镇恒同色、异镇异色、跨会话稳定；色相按 type 分带 —— 城/镇/村/宗门/渔村各占一段，避免满屏同色）。**不落协议**。
3. 地盘样式口径（建议）：城镇色填充 `a≈0.34` + 同色墨边 + 保留柔光；原**地皮色退为"内圈细环"**（可选），保证"这块地归谁"一眼可读。
4. ~~可选（D7）~~ **已拍板 D7=否**：聚落名牌纸签（`main.js:494+`）保持原样、**不染城镇色**。但**灵脉本体要带颜色** ⇒ 追加 R8（见 §9）。

**验收**：前端探针 —— 取同一 `st.id` 的多个建筑，断言其地盘像素主色一致；取不同城镇，断言色相不同；`?nobldg=1` A/B 出图。另需确认 `SPR_CAP` 命中率不劣化（拆出地盘后精灵种类反而变少）。

### R7：自动生成的城镇之间不能挨太近

**现状**

| 位置 | 事实 |
|------|------|
| `mapgen.js:1040-1053` | 同一区域格最多 `count=1或2` 座聚落；只做了**同格**去重（`usedCenters` + `pickCenterExcluding`，B2）。 |
| `mapgen.js:1044-1048` | 锚点在 `i*REGION_M ± 0.35*REGION_M`（`REGION_M=18` ⇒ ±6.3 格）内撒点，真实中心再由 `pickSettlementCenter` 取勘测半径 4 内的最高分格 ⇒ **两个锚点可以落在相邻格**，跨区域格边界处也可紧邻。 |
| `mapgen-config.js` | **没有任何"聚落最小间距"参数**。 |

**改法**

1. 新增 `CFG.SETTLE_MIN_DIST`（单位：格，`hexDist` 口径）。参考量：城镇足迹 `TOWN_R=3` ⇒ 中心距 < 7 格时两镇足迹必然重叠。**✅ 已拍板 D6 = 7 格**（即"贴边、恰好不让两镇地盘重叠"的**下限**；不再是保守的 12）。
2. `settlementsFor` 增加**抑制层**：
   - 同格内：`k` 循环时除"同格去重"外，再要求 `hexDist(候选, 已落中心) >= MIN`（在 `prospectArea` 的候选表里继续降序找下一个满足者，而不是直接放弃）；
   - 跨格：新函数 `rawSettlementsFor(i,j)`（**无抑制**）供邻域查询；只有 **`(i,j)` 字典序更小**的邻格聚落参与抑制 ⇒ 天然无环、确定、不递归（邻格自己也只看更小者）。两张缓存：`settleCache`（带抑制，对外）+ `settleRawCache`（无抑制，仅内部）。
3. 服务端与预览页共用同一份引擎 js ⇒ 天然一致；**前端不参与**聚落生成，无需改动。

**副作用**：聚落总数下降（同格双镇常被抑制、区域格边界处的镇被抑制），世界变"疏"。这是需求的直接后果；**✅ 已拍板 D6=7**（较宽松的间距，抑制强度最小，聚落数下降幅度也最小）。

**验收**：新增 `verify/check_settle_spacing.mjs` —— 抽样若干区域格（含 3×3 邻域），断言任意两聚落中心 `hexDist >= SETTLE_MIN_DIST`；并统计聚落总数变化（与旧版对拍给出下降幅度，供用户判断）。

## 2. 三个容易踩的实现细节（先记下来）

### 2.1 小灵脉底座恒为 0
见 R3 的表格。**严格 `> 0.70`** + `LIFT_CORE[2] = 0.70` + u16 量化 ⇒ 小灵脉在山地上**没有底座**，只画峰体（2.03~2.17 uR）。这比"hScale 偏小"更能解释实机观感。

### 2.2 「从属格」不要进 `comm.veins[]`
从属峰必须只通过 `fields().vein` 表达。一旦写进 `comm.veins[]`：
- 灵脉名牌会多出（`main.js:1208-1214` 逐 vein 出签，大灵脉一变七张签）；
- 世界统计（`main.js:1683`「灵脉 N」）与 `countVeins()` 会虚高；
- 群落内的五行发育（`mapgen.js:1552-1589`）与 `veinNear` 的最小距判定（`D_L_M/D_M` 等）都会被从属格污染。

### 2.3 地盘染色与精灵缓存的冲突
见 R6 的 ⚠。**结论：地盘不进 `spriteOf` 缓存**（缓存 key 不含 tint，加了会爆 512 上限）。

- **`veinTopU` 与 shader 口径必须同步**（`main.js:869-880` vs `renderer.js:196-210`）：动 `terrainBase`/`terrainBaseMin` 时漏改一处 → 灵脉名牌锚点漂移。

## 9. 新增需求与决策落地细节（2026-09-15 09:50 追加）

### R8：灵脉要「带有颜色」（来自 D7 附加要求）

D7 否掉了「名牌染城镇色」，但同时要求**灵脉本体带颜色**。现状灵脉峰走水墨单色（`propSpriteFor` 只换图集帧，不带色相）。**色源已就绪**：`vein-skin.js` 的 `elements[].glow`（五行 `ELEMENT_RGB`）与 `variants[].glow`（异灵根 `VARIANT_RGB`），且契约已与 `mapgen.js` 对齐，无需新增数据。

**待细化（P7 开工前定）**——着色载体，三选一或叠加：

| 方案 | 做法 | 代价 |
|------|------|------|
| ① 峰体着色 | 图集改"白模 + 顶点/实例色" | 最大：要重做精灵图集与 `propSpriteFor` 通道 |
| ② 峰下地台 / 色环 | 灵脉格地面画一层元素色六边形光晕（复用 R6 的 `plateAt` 思路；灵脉格无建筑 ⇒ 需独立绘制，不占精灵缓存） | 最小，推荐 |
| ③ 地名签描边色 | 灵脉签边框取元素色 | 很小，推荐 |

**建议 ② + ③**：不动图集，只加一层色环 + 签色，五行/异灵根一眼可辨。

### R9：灵脉格禁路、道路绕行（D8=是）

- 现状：B 版路网 `bfsRoad` 只依赖「该边 + 静态地形」，灵脉格当前**可通行**（`edgeKeep` 只按地形高度衰减）。
- 改法：给灵脉格（中心 + 从属）设"不可通行 / 极高代价"闸；`bfsRoad` 的回退路径（找不到路时）**必须也不许**穿灵脉格——宁可断路也不穿。
- **必查副作用**：两个聚落被一条灵脉（7 格群）隔开时，会不会双双变孤岛。验收要断言"每个聚落至少有一条**不穿灵脉格**的连接路径"；若做不到，就把"硬禁"放宽为"高代价（低优先）"，而不是让它断。
- 回归面：`w3_bfs_road`。**只加功能断言，不动墙钟阈值。**

### D1（第 4 档「从属」）契约改造清单

1. `vein-skin.js`：`levels` 3 → 4。前 3 档 `level` 值语义不变（0 大 / 1 中 / 2 小，须与 `veins[].level` 一致），从属档占新下标（建议 `level: 3`，排最后、`hScale` 最小）；四档 `hScale` 严格递减、**可视高度互不重叠**。
2. `main.js:960` 一带：`iElev = (level + elev) / 4`（原 `/3`）；`renderer.js:196-210`：`vz = clamp(iElev,0,1)*4`、`level = floor(vz)`、`elev = frac(vz)`；`min(floor(vz),2.0)` → `3.0`。分母改 4 后 max = `(3+1)/4 = 1.0`，仍恰不溢出。
3. `check_vein_skin.mjs`：文件头契约条目数（会话注释里的「34 项」）与会话断言同步；「占地 = 仅本格」三条 + 「等级不影响占地」按 D1/D3 改写（见 §5）。
4. `tools/prop_sheet.mjs`：看板增加第 4 档。
5. 从属格在 `fields()` 里写 `vein.level = 3`（**不是**"中心档 + 1"），且**不进 `comm.veins[]`**（§2.2 铁律不变）。

### D4（5 种建筑改为宗门附属）落地草案

灵枢殿 / 聚灵阵 / 祭坛 / 炼丹殿 / 炼器殿：不再绑「灵枢 / 高阶灵地」地皮。P4 草案 —— 只在 `type='sect'` 的聚落里生成，作为宗门中心的附属建筑（地皮名拟 `'宗门附属'`），出现数与宗门等级挂钩；是否保留"靠近灵脉"的加分由 P4 实机观感定。**若理解有偏（例如你是指每个宗门固定配置这几个建筑），P4 开工前一句话纠正即可。**
