## 一、P0 — 静默数据丢失 / 永久停摆

### S1. `MarkSettleDirty` 用区域格当区块格，演化结果永远送不到客户端

`Server/Zongmen/Services/MapWorldService.cs:368-371`

```csharp
public void MarkSettleDirty(string seed, int i, int j)
{
    EvictWithGate(seed, i, j);                                   // i,j = 区域格（WorldKeys.Region/Settle）
    BumpBlockRev(seed, i, j, TileMask.Settle | TileMask.Poi);    // 但 BumpBlockRev 的键是区块格 ca,cb
    _peopleCache.Clear();
}
```

`i,j` 的来源：`CityTickExecutor.cs:139-140` 收集 `dirtyRegions` 时调 `RegionOf(row.Id)`（`CityTickExecutor.cs:355-362`，从 `{区域i}_{区域j}_u{n}` 解析），是**区域格**；`:159` 原样传给 `MarkSettleDirty`。

而 `BumpBlockRev`（`MapWorldService.cs:748-753`）拼的键 `blk:<seed>:i:j` 必须与 `GetTileBlock`（`:764-767`）一致，后者由 `MapWsHandler.cs:182` 传入 `req.I/req.J` = **客户端块坐标 (ca,cb)**。

**后果**：tick 改的是 Settle/Poi 层，却在一个不存在的块键上 +1，真正包含该区域的块 rev 不变 → 客户端带旧 `lastRevs` 重拉时 `Need(bit)=false` → 服务端缺省 settle 层 → 建筑/人口演化**永久不可见**，无异常、无日志。这正是 `:737-743` 那段 C5 警告描述的失效模式。

**对照**：`ApplyPlaceChange`（`:1637-1638`）把 `regions`（区域格，用于 Evict）和 `blocks`（区块格，用于 Bump）分开传，是正确写法。

**修法**：拆成两个坐标系明确的 API —— `MarkRegionDirty`（Evict，收区域格）与 `MarkBlocksDirty`（Bump，收区块格）；或内部按区域包围盒反查覆盖块后逐块 Bump。

### S2. 重启把「当前世」的城市演化清空

`Server/Zongmen/Services/MapWorldService.cs:201-214`

注释写的是「清的是**上一世**的状态」，代码传的是当前世：

```csharp
var cur = _ledger.Current();
var removed = _subsystems.ClearWorld(cur.Round);   // ← 当前 round，不是上一世
```

`CitySubsystem.OnWorldChanged → CityStateStore.RemoveRound`（`CityStateStore.cs:298-311`）的 SQL 是 `DELETE FROM CityState WHERE Round=$r`，直接删库。而 `BindCurrentWorldToTick` 的全部调用点只有 `AttachTickPump`（`MapWorldService.cs:133`），也就是**每次进程启动一次**。

**后果**：`CityState` 是人口/等级/建筑的权威台账。每次重启删掉当前世 → `EnsureInitialized` 按骨架重建初始人口 ⇒ 演化几十天的成果归零；日志还打印"换世清空子系统世态: 第 N 世"，把数据丢失伪装成正常换世。

**修法**：启动时不应清当前世（要清的是 `cur.Round - 1` 的残留，或干脆只在真正换世时清）。建议抽出 `SwitchWorld(旧 round)`：`UnbindWorld → ClearWorld(旧Round) → BindCurrentWorldToTick`。

### S3. `/api/world/next` 换世后不重绑 Tick

`Server/Zongmen/Services/MapWorldService.cs:1190`

```csharp
public string WorldNextJson() => WorldJson(_ledger.Next(), "next");
```

全仓 `BindCurrentWorldToTick()` 唯一调用点是启动装配（`MapWorldService.cs:133` ← `Program.cs`），`MapEndpoints.cs:37-38` 只改台账。

**后果**：换世后 `TickPump._binding` 仍是旧 seed/round ⇒ 旧世继续写 `CityState`、继续烧 V8；新世没有 job（`_lastReconcileTick` 只在 `BindWorld` 里设），`/api/clock` 与 `/stats.tick` 报的是旧世时间。玩家看到"换世了但时间不动、城市永不演化"。这是设置弹窗的正常操作路径。

**修法**：`WorldNextJson` 内走 `UnbindWorld → ClearWorld(旧Round) → BindCurrentWorldToTick`，并清 `_expectedCache`。

## 二、P1 — 路径必现的功能失效

### S4. 期望集提供者吞异常，全格失败时对账删光演化 job

`Server/Zongmen/Services/MapWorldService.cs:162-167`

```csharp
try { json = lease.Vm.Call("citySettlementsJson", i, j); }
catch { continue; }                    // 无日志
```

`TickPump.MaybeReconcile`（`TickPump.cs:432-437`）的纪律是：**返回 null = 未知 ⇒ 跳过对账；返回空集 = 本世不该有 job ⇒ 全删**。这里任何 V8 调用/JSON 失败都被静默跳过；若 49 格全失败（VM 淘汰竞态、bundle 漏文件、出口分支丢失），`list` 为空且**不是 null** → 下一个对账周期（默认 360 tick）把本世所有 `TownEvolve/TradeEdge` job 删掉 ⇒ 整世演化静默停摆，日志只有一条"对账 -N"。

**修法**：至少 `Console.Error.WriteLine`；更稳的是记失败计数，超阈值整体返回 null 让泵跳过对账。

### S5. dump/hydrate 不承载多小队结构

`web/js/crew/crew-bridge.js:388`（hydrate 只造单队字段）、`:453`（dump 遍历全量 pawns 塞进一个 squad）、`:506`（`id: state.squadId`）

```js
// hydrate
squadId: str(c.squad.id, 'squad-1'),          // 没有 squads / curSquad
// dump
for (var m = 0; m < state.pawns.length; m++)  // 全量 pawns → 单 squad.members
```

面板侧 `normalizeSquads` 会把"没有 squads"补成"一队装全员"，`curSquad` 归 `sq1`；`dump` 又把创建顺序当队内顺序导出。

**后果**：接后台（`?crewapi=1`）后，多队分组、队内站位、队间顺序、当前队、队伍改名全部一次往返即丢。违反"队员归属唯一真源 = members 数组顺序"这条契约。

### S6. 背包页的「服用 / 研习」按钮无人响应

生成端 `web/js/crew/crew-panel.js:1166,1169` 对丹药/功法输出 `data-act="use"`；监听端 `:237-239` 只处理两种：

```js
if (act.getAttribute('data-act') === 'equip') doEquip();
else if (act.getAttribute('data-act') === 'unequip') doUnequip(...);   // use 落到 else 之外，直接返回
```

能力页（`:227-229`）有 `else if (a === 'use') doUse();`，背包页漏了。点丹药格 → 详情卡出现「服用」→ 点击：不弹提示、不消耗物品、无任何反馈。

### S7. 卸下最后一件法宝 → 队列归 0，违反 `TALISMAN_MIN`

`web/js/crew/crew-model.js:777-783`

```js
if (slot === 'talisman') {
  for (var i = 0; i < pawn.queue.length; i++) if (pawn.queue[i] === it) { pawn.queue.splice(i, 1); break; }
  pawn.gear.talisman = pawn.queue[0] || null;      // 队列只有 1 件时变空

```

`CFG.TALISMAN_MIN = 1`（`:39`），`probe`（`:946`）与契约都要求 1~4。能力页把"卸下"做成普通按钮，点一下就进入非法状态，`dump` 出去的 `queue: []` 服务端按契约判坏。

**修法**：`queue.length === 1` 时拒绝卸下（提示"至少留一件法宝"），或明确把最小队列改成 0 并同步改 probe/契约。

### S8. 气血/灵力条只在任务页刷新

`web/js/crew/crew-panel.js:1289-1309`

```js

  var cp = curPawn();
```

## 三、P2 — 需特定条件触发的静默错误

### C1. 慧根 +4%（应 +6%）

`Engine/js/chargen.js:130` 与 `web/js/crew/crew-model.js:70` 都写 `修炼速度 +4%`。但 `1d808d7` 原值是 `+25%`（旧 `TRAIT_PAIRS`），按"原值 ÷4"应为 `25/4 = 6.25 → 6%`。同批的 `grit 受伤恢复 +13%`（原 50%）、`diligence +9%`（原 35%）都遵了 ÷4，只有这条缩了 6.25 倍。两处同错，不是互相不一致。

### C2. 队 id 去重是死循环

`web/js/crew/crew-model.js:652-657`

```js
var base = out[i].id;
while (seenId[out[i].id]) out[i].id = base + '_' + (i + 1);
```

循环体每次都赋**同一个**值。若该值已被前面的队占用（例：`['sq1_3','sq1','sq1']`，i=2 时候选正好是已占的 `sq1_3`），条件恒真 → 永不退出。`normalizeSquads` 每次渲染前都调（`crew-panel.js:331`），一旦命中，整个面板假死。

**修法**：`var n = i + 1; while (seenId[base + '_' + n]) n++; out[i].id = base + '_' + n;`

### C3. 解散小队的二次确认可被双击击穿

`web/js/crew/crew-panel.js:478-486`：第一次点击置 `delAsk = id` 并**同步** `renderSquadPage()`，`×` 原地变成「确认」，按钮右对齐扩展、右边缘像素不变 → 双击第二下直接命中 `delAsk === id` 分支执行解散。3 秒窗口形同虚设，且不可撤销（队名丢失、成员并入第一队）。**【待实测】**：需真机双击确认像素位置。

**修法**：确认按钮换位置/加 150ms 冷却，或改成顶部一次性 toast 里的「确认」按钮。

### C4. 物品名 / 物品 id / 弟子 id 未转义进 HTML

`web/js/crew/crew-panel.js:902-903`

```js
'title="' + esc(M.SLOT_NAMES[sk]) + (it ? ' · ' + it.n : ' · 空') + '">'   // it.n 未转义
```

同一行前一段刚 `esc()` 过槽位名，紧接的 `it.n` 漏了。另有 `:353` 的 `data-id="' + p.id + '"`、`:392/444/520` 把 `sq.id` 裸拼进 `querySelector('.sq-sec[data-sq="' + id + '"]')`（带引号直接抛 `SyntaxError`，让整个点击处理失效；而 `:383` 渲染时又用了 `esc()`，读写两套）。

触发面：接后台或存档被手改时，`bag.items[].name` / `members[].id` 含 `"` 或 `<`。

### C5. 移动端拖拽实际不可用

`crew-panel.css:166-174`（`.sq-hd`）、`:241-250`（`.rp-row`）只有 `user-select: none`，没有 `touch-action: none`；外层 `.crew-body` 是 `overflow-y: auto`（`:141`）。拖动全部基于 pointer 事件并在 document 的 `pointermove` 里 `preventDefault()`（`crew-panel.js:792/816`），但 `preventDefault` 阻止不了已由 `touch-action: auto` 交给浏览器的 pan 手势 → 手指一动即 `pointercancel`，`endPawnDrag` 按"未落点"回写。

反向问题：`.cw-scroll` 设了 `touch-action: pan-x`（`:653`），导致任务矩阵区域**无法纵向滚动**。文件里有 `≤760px` 的移动端断点，说明移动端是目标平台。

### C6. 拖动途中收到 `setSquad` → 旧 DOM 顺序写回新 state

`web/js/crew/crew-panel.js:701-714`：`applyPawnDrop` 从按下时抓的 `st.secs`（已脱离文档的旧 `#sqSecs`）读 `data-id` 顺序，却写进**新的** `state.squads`。`setSquad`（`:1499-1505`）会整体换 `state` 并 `renderAll`，但 `_pDrag` 仍指向旧节点。

后果：bridge 一次 `patch`（增删成员）落手时，新人被塞进第一队、被删的人被重新写回 members —— 与服务端反向。

### C7. 事件流没按契约实现

`web/js/crew/crew-bridge.js:597-605`

```js
var ev = { kind: kind, at: Date.now(), detail: detail || null, contract: null };
...
e2.contract = getContract();      // 文档 §14.0 明令废弃的"发整份契约"
```

- 缺 `v / id / seq / base`：无法幂等、无法检丢包、服务端无法判冲突
- 带整份 `contract`：会把服务端正在跑的 `activity/vit` 覆盖回去
- 只包装 4 个写操作（`:626` `['equip','unequip','useItem','cyclePriority']`），`movePawn`、建队/改名/解散/队排序全不包装；`type` 用简写 `use/prio`，与契约 `item.use`/`job.priority` 不一致；`:635` `slice(0,2)` 丢掉 `equip` 的 `idx`，`detail.args` 里塞的是对象引用不是 id

现状：仓库里没有任何 `onChange` 订阅、也没有 `POST /api/crew/events` ⇒ 所有写操作实际**一条都不落库**，刷新即丢。

### C8. `usedNames` 原地写入破坏确定性

`Engine/js/chargen.js:548-568`：撞名重试靠"换 salt 重掷整个人"，且 `used` 是调用方传入并被本函数写回。同一 `(worldSeed, settleId, round)` + 同一个 `usedNames` 调两次，第二次每个 slot 都重试到 guard=23 ⇒ 整池换人（灵根/天赋/特质全变）。方案文档 §十二.4 的验收项"同参数调两次 `JSON.stringify` 完全相同"会 FAIL。

**修法**：`used` 用浅拷贝（`var used = Object.assign({}, opts.usedNames)`），或返回新增名字由调用方合并。

### C9. `pop` 只缩不放，且能跌破类型区间下限

`Engine/js/chargen.js:541`

```js
if (st.pop) size = Math.min(size, Math.max(1, Math.round(st.pop / 50)));
```

文档写"池量 村落 3~4 / 坊市 4~6 / 仙城 6~9 / 宗门 2~5（**`pop` 可再放大**）"。实现只有 `Math.min`：`{type:'city', pop:200}` → 4 人（仙城区间 6~9 直接掉到村落水平）。

### C10. 24 条特质只有 7 条有数值效果

`web/js/crew/crew-model.js:411-417` 只处理 `血旺/坚毅/胆识/龙象之力/力大无穷/铜皮铁骨/耳目清明`。`过目不忘/妙手回春/心如止水/天生魅体/五行亲和/天生灵眸/福缘深厚/道心通明/天生道体` 等只有文案；「力大无穷 负重 +5%」在 `loadMax()`（`:483`）里没有任何特质分支。玩家看到加成、数值不变。

### C11. 三个 JS 出口缺 `Invoke` case

`Engine/WorldModule.cs:49-78` 的 switch 里没有 `domainRadius` / `archetypeOf` / `bumpRoadVer`，而 `Engine/js/mapgen-server.js:517-524` 都定义了。当前 C# 侧无调用点（已 grep），所以不炸；任何人写 `Call("domainRadius", …)` 就运行时 500。**铁律 1 的潜伏缺口**，建议补 case 并加"出口键集 ⊆ case 集"的静态判据。

### C12. `JsVmPool.Dispose` 无视 `InFlight`

`Engine/JsVmPool.cs:284-291`：`foreach (var vm in _vms.Values) vm.Dispose();` 未跳过 `InFlight > 0`。LRU 淘汰（`EvictLocked`）遵守了这条，进程级 Dispose 没遵守。`JsVm.cs:30-32` 自己写着"Dispose 一个正在跑 Call 的 V8ScriptEngine 会直接崩进程"。关机时 `ApplicationStopping` 只 `UnbindWorld`、不等当前 tick，并发路径真实存在。

### C13. `SqliteVirtualContext.Dispose` 的 Flush 是死代码

`Storage/SqliteVirtualContext.cs:203-208`

```csharp
public override void Dispose() {
    if (_disposed) return;
    _disposed = true;                // 先置位
    ...
    try { Flush(); } catch { }       // Flush 首行 if (_disposed || _pending.IsEmpty) return;
```
