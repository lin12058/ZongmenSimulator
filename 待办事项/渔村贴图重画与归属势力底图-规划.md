### 1.2 渔村的贴图从哪来（这是 A 的落点）

真源只有一处：**`web/js/bldg_ink.js`**（运行时 Canvas 精灵，`KINDS[种类]` 函数表）。

- `KINDS['民房']`（`bldg_ink.js:1648-1669`）：前屋 + 后屋错落 + 檐口茅草 + 篱笆 + **晒竿晾布** + 炊烟。**纯内陆民居**。
- `KINDS['仓库']`（`:1671-1688`）：大屋 + 门闩 + 两侧粮囤 + 板车。也是内陆货仓。
- `waterDeck(S)`（`:904-921`）：建筑格是水时垫的"干栏木台 + 入水桩脚 + 水色压深"，由 `paint()` 在 `spec.onWater` 时调用（`:1877`）。
- `paint()`（`:1859`）→ `KINDS[spec.kind] || KINDS['民房']`（`:1870`）；`spriteOf()`（`:1909`）按 **kind/朝向/变体/R档/detail/tier/water/plate/onWater** 缓存精灵。
- 远视图图标：`main.js:489-490` `ICON_FN = { …, fishing: drawVillage, … }` —— **渔村与村落共用同一个图标**。
- 离线看板：`tools/ink_buildings.mjs`（26 种 SVG，产出 `docs/建筑贴图/`）、`tools/bldg_town.mjs`（真实聚落平面图，支持 `--type=fishing`）。

> 结论：**「渔村没重画」的本质是 —— 水里盖的还是内陆民房**，只多了一块木台。所以看着像"海上飘着几个村子"，没有渔村的样子。

### 1.3 地盘（R6）与"归属势力"是什么关系

- `main.js:943-961` `townColor(st)`：由 `(st.q, st.r, type.length)` 哈希 → HSL，色相按 type 分带（`city:22 town:46 village:142 sect:268 fishing:196`）±14° 抖动。
  ⇒ **同镇同色、异镇异色、跨会话稳定**，但它是"**区分同屏不同城镇**"的色，**不是归属**。
- `bldg_ink.js:368` `plateAt(ctx,o)`：R10 已从"实心块"改成**中空正六边环**（`rIn 0.80 ~ rOut 0.90`）。`main.js:1024-1027` 逐格调它，`tint = townColor(it.st)`。
- 灵脉另有同款环（`main.js:1184-1194`，元素色）—— 两套环**同一"六边地台"语汇**，这是 B 要复用的现成骨架。
- `owner` 字段：协议里有（`Server/Zongmen/Domain/MapMessages.cs:82 Owner`），引擎恒空（`mapgen.js:1204 owner: ''`；`main.js:71` 注释亦自陈"后端 mapgen 尚无归属系统"）。

### 1.4 匾额引线的锚点链（C 的现场）

`drawNameBanner(ctx, x, anchorY, text, opt)`（`main.js:513`）内部：
```
引绳: moveTo(x, bottomY) → lineTo(x, anchorY)     // 纯竖直
落点: arc(x, anchorY, …)                          // 圆点画在 anchorY
bottomY = anchorY - lead     (lead = max(5, fs*0.62))
```

| 地物 | `x` | `anchorY` | 由谁算 |

### 4.2 实测现象（1400×900，z=3.2，hexR=8 ⇒ 屏幕 R = 25.6px；以下为原图像素，目测 ±20px）

| 对象 | 落点圆点 | 应该指的地方 | 空档 |
|------|----------|--------------|------|
| 灵脉「金属矿脉」lv0 | ≈(523, **236**) | 峰尖 ≈(520, **290**)（脉格心 ≈(520,450)） | **≈54px ≈ 2.1R** —— 圆点明显悬在半空，引线没搭到峰上 |
| 古井村 | ≈(**811**, 320) | 聚落中心格 x=811 ✓ / 建筑群横向中心 ≈784 ⇒ **右偏约 1 格**；且落点下方是**空地格**，不是任何一座房子 | 横向 ≈27px |

用户看到的"竖线和点对不上"= 这两类偏差叠加：**点悬空（灵脉）+ 点扎在空地/整体偏一格（聚落）**。

### 4.3 根因

**C-1 聚落：锚点是"合成点"（代码事实，无需目测）**

`bldgAnchor()` 把两个不同来源的坐标拼在一起：
```js
var ax = ANC_GEO ? (x0 + x1) / 2 : st.x;   // ← 横向: 聚落中心格
var y0 = rs[Math.min(rs.length - 1, Math.floor(0.25 * rs.length))]; // ← 纵向: 建筑格 y 的 p25
st._anc = { x: ax, y: y0 };
```
⇒ 落点 `(中心格 x, 建筑群 p25 y)` **通常不对应任何一个真实建筑格**，所以会扎在村里的空隙或边缘。
（注释里记着 2026-09-14 的三次返工，都是在修"签子位置"，但**这个合成点的性质没变**。）
另有隐患：`st._anc` **首次绘制即缓存**，若那一刻 `st.buildings` 还没到 ⇒ `y0 = Infinity` ⇒ 永久退化成 `(st.x, st.y)` 且不再重算。

**C-2 灵脉：`veinTopU()` 是包络估算（源码自陈）**

```js
function veinTopU(v) {
  … var baseU = (3.3 + 1.2 * 0.86) * bhs * tb;        // bhs 来自 elevAtTile(v.q,v.r)
  var peakU = (3.3 + 1.2 * (lv.hRand[0] + lv.hRand[1]) * 0.5) * lv.hScale * VS.shape.sizeScale;
  return baseU + peakU + 0.35;                         // +0.35 是"不贴峰尖"的**故意余量**
}
```
注释原话："随机抖动项取包络中值 (hrand=0.86) —— 签位只需 ≈峰尖高度, **不必逐格精确到 hash**"。
⇒ 设计上就有偏差，`+0.35R`（≈9px）是允许的，但实测 **2.1R ≈ 54px** 远超它，说明**至少还有一处口径不一致**。排查顺序：
1. `elevAtTile(v.q, v.r)` 该格所在区块**是否已加载**（未加载 ⇒ `bhs` 走错档 ⇒ `baseU` 偏大）。⚠ 灵脉签的 `topU` 是在**世界系阶段**算的（`:1196`），此时区块可能还没到齐。
2. `VS.shape.terrainBase / terrainBaseMin / sizeScale` 与 `renderer.js` 的 `PROP_VS` 灵脉分支**逐项对齐**（`main.js:802` 自称"完全一致"，需复核）。
3. `lv.hScale` 的实际取值 vs `VEIN_SKIN.levels[]`。
4. `hexR * z` 是否就是 renderer 里 sprite 的实际屏幕半径（有无 dpr/sizeScale 二次缩放）。

### 4.4 候选修法（三选一，待拍板）

| 方案 | 做法 | 优缺点 |
|------|------|--------|
| **C-a 落点改扎真实格**（推荐） | 聚落：取**离"中心格 x"最近的建筑格**（或直接取**核心建筑格**）作落点；灵脉：取**脉格心** `v.x/v.y`（品红十字那个点） | 语义最清晰："签指实体"；引线可能略长/略斜（需把引线改成**折线**：签底竖下 → 折向落点）。实现集中在一个函数 |

### 8.4 本次顺带发现并修掉的两处**契约自身**问题

1. **`frontend_smoke` 解码字段审计误报**：B 新增的 `st._fac` / `st._facV` 被「前端读取必须落在解码器字段集内」判红。这两个是**客户端本地 memo**（与既有 `st._anc` 同类）。修法 = 按**项目约定**整体放行 `_` 前缀属性（线路 protobuf 字段一律不带下划线前缀 ⇒ `_xxx` 只可能是前端自挂缓存），不必每加一个缓存就改白名单。⚠ 这类误报**已发生两次**（`_anc`，然后 `_fac/_facV`），故这次改成前缀规则而非再补白名单。
2. **`check_calc_local` 的 S5 判据是假红**：原判据只看 hybrid 档「首屏最长任务 ≤ 50ms」，实测恒红 **~250ms**。做**归因 A/B** 后真相大白 —— `server` 档（**一行本地算都不跑**）同样 **249ms**，`ab` 档 254ms ⇒ 那 250ms 是 **WebGL 上下文/着色器/图集**的启动开销，与本改造无关。判据已改为「**hybrid ≤ server + 40ms 余量**」，并把三档的最长任务数打进摘要行（数字不再被藏起来）。
