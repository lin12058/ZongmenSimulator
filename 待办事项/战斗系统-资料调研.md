# 战斗系统 —— 资料调研（凡人修仙传 · 觅长生）

> 目的：为「在这个世界里做一套**战斗系统**」，把两作最成熟的两块设定——**五行灵根**与**斗法/战斗**——逐条拆开，并对照**本项目已有的地基**，摊开可嫁接的接口与必须绕开的坑。
> 边界：**本文不含实施方案**。§六 只给候选路线与倾向，§七 列必须拍板的问题。定案后再写《战斗系统-实施方案》。
> 相关已有档：`docs/灵脉地图设定.md`（五行相生相克/异灵根/群落，**本项目五行设定的真源**）、`docs/设定.md`（世界观/化身/灵气复苏）、`docs/玩家信息表设计.md`（`PlayerSect` / `disciples`）、`待办事项/人物系统-资料调研.md`（个体建模、LOD、`SectCultivation` 空壳 job）、`docs/游戏时钟与Tick演化框架方案.md`(v2.1)、`.workbuddy/memory/MEMORY.md`。

## 〇、一页纸

你要做的「战斗」，剥开是四个各自独立的问题：

1. **谁在打**——个体修士 / 一队弟子 / 整座宗门 / 一座城？（决定实体层级与 N 上限）
2. **凭什么赢**——数值（境界×功法×法宝）压过去，还是**五行相生相克**这类**克制关系**决定胜负？
3. **玩家管不管**——像《觅长生》那样每回合出牌亲操，还是自动结算只给战报？
4. **在什么时候算**——即时结算，还是挂到 Tick 框架里当一个 job（离线也在推演）？

两作给出的答案**恰好相反**，而这正是本调研最有价值的部分：

| | 凡人修仙传 | 觅长生 |
|---|---|---|
| 战斗呈现 | **法宝战的战术博弈**（试探/规避/破绽/底牌） | **卡牌式回合制**（抽灵气→打神通） |
| 灵根作用 | 决定**修炼速度与境界上限**（成长曲线） | 决定**每回合抽到什么属性的灵气**（战斗资源） |
| 五行关系 | 功法/法宝克制（辟邪神雷克邪修…） | **相生=连击，相克=增伤**（战斗核心机制） |
| 胜负手 | 底牌 × 情报 × 撤退判断 | 灵气结构 × 卡组构筑 × 出牌顺序 |

**一句话结论**：**凡人给的是"骨架"（境界链 + 灵根梯度 + 法宝/神识/符箓/遁术这套 orthogonal 的战力维度），觅长生给的是"接口"（把五行相生相克做成一张可计算的伤害/连击表）**。而本项目最幸运的一点是——**五行相生相克（含异灵根）在引擎里已经实现了**，而且是**为灵脉生态**实现的（`SHENG`/`KE`/`DUAL`，见 §五）。战斗系统在"五行"这一层几乎是**白捡**的。

三条先行结论（§六展开）：

- 最值得照搬的是 **觅长生的"灵气牌池 + 相生连击"**——它把玄学的"五行相克"变成了**确定性的、可离线复算的规则**，与本工程"全随机走 `hash01`、禁运行时 RNG"的纪律**天然同构**。
- 最需要你拍板的是 **战斗粒度**（个体 / 部队 / 宗门）——它决定这套系统是「加法宝字段」还是「加一整个实体层」，和人物系统是同一道选择题。
- 最大的隐藏成本不是数值，是 **"一场战斗一次同步重算"**。本工程已在 `commitPlace` 上被 405~443ms 的同步门闩教育过（memory 铁律）；战斗只会比它更频繁。**解药同样已经用过一次：把战斗做成 Tick 的 L0 纯函数 job，削 `dt` 摊批。**

## 一、参考资料 A：凡人修仙传 · 灵根设定

> 出处：起点问答《凡人修仙传的灵根设定》多条、作品设定总表。[^1][^2]

### A-1 灵根的两条轴

凡人的灵根不是"一个数值"，是**两条正交轴**：

- **属性**：金、木、水、火、土（基础五行）；金木水火土之外还有 **风、雷、冰、暗**（变异）。
- **属性数量**：1 种 / 2~3 种 / 4~5 种。

| 称谓 | 属性数 | 修炼速度 | 典型结局 | 备注 |
|---|---|---|---|---|
| **天灵根** | **单一**属性 | 普通灵根的**数倍** | 结丹**无瓶颈** | 各大门派争抢；结丹期潜力人选 |
| **真灵根** | 2~3 种 | 较快 | 有机会筑基、结丹 | 每种属性"充裕" |
| **伪灵根** | **4~5 种** | **很慢** | 多数**终生停在炼气期** | 韩立即"五行缺金"四灵根 |
| **变异灵根** | 2~3 种五行**异变升华** | **不下于天灵根** | 潜力特殊 | 风 / 雷 / 冰 / 暗 |

### A-2 必须抄下来的那个"反转"

凡人灵根设定里**最反套路、也最值得作为设计支点**的一条：

> **灵根越少 ⇒ 前期修炼越快；但进阶「炼虚」必须五行合一 ⇒ 灵根越少，后期越麻烦。**

- 多灵根（伪灵根）前期是**负资产**（修炼慢、难筑基），后期是**正资产**（五行齐备，炼虚门槛低）。
- 天灵根前期爽，到炼虚期才补"五行合一"这一课。
- 这构成一条**完整的成长曲线反转**，而不是"品质越高越强"的线性数值——**这正是"有取舍的设计"的范本**（对照《人物系统-资料调研》§A-2《最强祖师》"单一灵根加成更高"是同一个思路的另一面）。

### A-3 灵根可以后天改

- `补天丹`：**"可弥补灵根的不纯，精炼先天灵根"**。
- `器灵根` / `丹灵根`：借用灵物**补缺增加**灵根。
- ⇒ **"灵根"不是开局锁死的常量**，而是可被**丹药/机缘/宝物**改写的一个字段。对角色的**长期养成线**极其重要。

### A-4 灵根与地貌的呼应（本项目已引用）

`docs/灵脉地图设定.md` §4.1 已经把五行灵根映射到地貌意象（金=矿脉/剑意，木=灵木/药田，水=深潭/雾瘴，火=熔岩，土=厚土），与本项目引擎 `LANDFORM` 表逐字对应。**这条是两作设定与本项目唯一"已打通"的地方。**

## 二、参考资料 B：凡人修仙传 · 境界与斗法

> 出处：作品设定总表、打斗逻辑分析、战斗细节书评。[^2][^3][^4]

### B-1 境界链（战力骨架）

```
下境界: 炼气(1~13层) → 筑基 → 结丹 → 元婴 → 化神
中境界: 炼虚 → 合体 → 大乘
上境界: 渡劫  (过此层飞升)
除炼气外，每境界分 初 / 中 / 后 / 大圆满
```

- **寿元与境界硬绑定**（人界口径）：炼气百岁 → 筑基二百 → 结丹四五百 → 元婴千岁 → 化神两千岁。
- 突破成功率**指数级下降**（"结丹成功率仅为筑基期修士的百分之一"）⇒ 境界之间是**断崖，不是斜坡**。
- ⚠ 对战斗的意义：**境界差 = 碾压**。凡人自己写明"炼气期难敌筑基期"——**越阶挑战在人界几乎不可能**（灵界才允许）。所以纯数值对抗里，**境界必须是主导项**，其余维度只能"补差"，不能"翻盘"（除非靠克制/情报/底牌，见 B-2）。

### B-2 斗法的六个维度（正交战力来源）

凡人战斗之所以被称"逻辑流天花板"，在于**战力不是单一数值**，而是六个可分别准备、分别克制的维度：

| 维度 | 设定 | 战斗中的作用 |
|---|---|---|
| **功法层次** | 青元剑诀 1~3 层出剑芒 / 4~6 层护体剑盾 / 7~9 层剑影分光 / 10~13 层大庚剑阵 | 决定**输出与防御的方法论**（不只是数值） |
| **法宝品阶** | 法器 → 法宝 → 古宝 → 通天灵宝 → 玄天之宝 | 有**属性克制 / 认主要求 / 神识消耗**；本命法宝可随修为成长 |
| **神识** | 大衍诀专修；"剑光分化数十道**迷惑对方神识锁定**" | **命中/锁定/反锁定**的独立维度 |
| **符箓** | 七星草制符纸 | **一次性底牌**（消耗品） |
| **遁术** | 罗烟步、血影遁、血影遁"瞬间逃匿百里" | **撤退成功率**——"打不过就遁"是生存法则 |
| **灵兽 / 阵旗** | 噬金虫、阵旗数百杆精确布置 | **战场预置**（战前布局算战力） |

### B-3 战斗风格（行为模板，可直接做 AI）

韩立的每场斗法都有**固定战术节拍**：

> **先试探 → 再规避 → 找破绽 → 控距离 → 最后一击必杀**；
> 且**永远保留至少三张对方不知道的底牌**。

- 典型：*对王蝉*——开局不硬刚，地面规避+拉扯试探摸清鬼术套路，再用法器牵制分割攻势，在对方招式落空露破绽瞬间切攻击模式精准反杀。
- 关键设计：**"每一次碰撞都是一次探测"**——用法宝硬撼时反向推导对方法宝内部灵纹结构，几次碰撞后拼出最脆弱那道灵纹的位置，下一剑劈在那里。
- ⭐ 对 AI 的启示：**战斗不是比总战力，而是"信息 + 时机"**。若本项目做自动战斗，**"试探→破绽→斩杀"三相位**比"高战力碾压"更有修仙味，且**天然可确定性化**（相位由 `hash01` 决定探测结果）。

## 三、参考资料 C：觅长生 · 灵根设定

> 出处：官方百科（角色状态/灵根/境界/悟道/功法/法宝）、开局灵根选择攻略。[^5][^6]

### C-1 灵根的数学定义（最可抄的一条）

觅长生的灵根**不是等级，是权重向量**：

> **角色灵根分金木水火土五个数值；获得某属性灵气牌的概率 = 该属性灵根值 ÷ 五灵根值之和。**

- 即：**灵根 = 抽卡权重表**。
- "灵根精纯和修炼速度挂钩，但影响不大"——**灵根在觅长生的主战场是战斗，不是成长**（这一点与凡人**相反**，见 §四对比）。
- 单/双灵根的差异在于**"连击"**：**需要连击的流派必须双灵根**（双灵根才会稳定抽到相生所需的第二种属性）；**剑修、少数流派可走天灵根**（不吃连击）。
- 门派与推荐灵根（**官配**，可直接做本项目宗门的"擅长灵根"）：

| 门派 | 主修五行 | 推荐灵根 |
|---|---|---|
| 金虹剑派 | 金 | 金 / 金土 |
| 离火门 | 火 | 火 / 火木 |
| 白帝阁 | 金(土) | 金(土) |
| 竹山宗 | 木 | 木水 / 木 |
| 星游派 | 金 | 金水 |
| 化尘教 | 火 | 火土 |

- 一句黑话总结：**"遇事不决天灵根。"**（天灵根还能直接拜师、拿上品法器礼物）

### C-2 与灵根耦合的"悟道树"

悟道分 **金、木、水、火、土、神、体、剑、气、丹、器 11 个方向**，各有独立境界（一窍不通→初窥门径→略有小成→融会贯通→道之真境→大道已成）。

- ⭐ **"五行只占 5/11"**——其余 6 条（神体剑气丹器）是**跨五行的通用维度**。这给本项目的启示是：**战斗维度不要被五行锁死**，需要有"不属于任何一行"的通用轴（本项目已有的 `RES_ORDER` 里 `丹`/`器` 正对应）。

## 四、参考资料 D：觅长生 · 战斗系统（本项目最该抄的一套接口）

> 出处：官方百科·战斗系统、游民星空入门攻略、战斗机制解析。[^5][^7][^8]

### D-1 核心循环（卡牌式回合制）

```
回合开始 → 抽固定"总量"的五行灵气牌（属性按灵根权重随机 roll）
        → 消耗指定属性/数量的灵气牌，打出「神通」
        → 相生触发「连击」 / 相克提升伤害
        → 回合结束，灵气保留至"上限"，超出的消散
```

- **灵气值是核心**："灵气系统是游戏战斗系统的核心，换句话说也能认为是整个游戏的核心。"
- **每回合吸收量固定**（基础 5；元婴期五行功法加 2/4/6），**但属性随机** ⇒ 逼迫玩家**构筑"灵气转换"技能**（把废属性转成要用的属性）。
- **屯牌有上限**（回合结束灵气必须降到上限，不能无限屯）⇒ 消除"苟到最后一把梭"。
- 难度档对战斗的调节很直白：极难 = 玩家受伤 +50% / 敌方受伤 -50%。

### D-2 五行相生相克 → 战斗规则（**本文最关键的移植目标**）

觅长生把玄门"五行"落成了**两条可计算规则**：

| 关系 | 规则 | 战斗效果 |
|---|---|---|
| **相生**（五行轮盘**相邻**） | 木生火、火生土、土生金、金生水、水生木 | **连击**：上一张牌与当前技能构成相生 ⇒ 触发额外效果 |
| **相克**（**不相邻**） | 金克木、木克土、土克水、水克火、火克金 | **增伤**：克制关系的出牌顺序提升伤害值 |

- 记忆法：**"相邻相生，不相邻相克"**（作者用"五行轮盘"替代了背诵，本项目 `SHENG`/`KE` 数组更直接，见 §五）。
- 实例：**金刃**——需 3 张金灵气牌；练气期 4 伤，**若上一张是土系技能则伤害 +2**（连击）；化神期 36 伤、连击 +16。
- 实例：**金芒决 3 级 +4、初始 +2 ⇒ 固定 +6**，能把基础"金刀"从 4 伤抬到 10 伤；帮派进阶技能可达 13~15 伤。
- 实例：**石肤术**是"土金双属性"，**方便同时做相生与相克的桥接**；**土属性抽金气**的技能可稳定在前期打出"一回合 20 点左右"。

⭐ **三条可直接固化为公式的结论**：
1. **相生 = 连击（条件触发额外效果）**，是**顺序依赖**（"上一个技能的属性"决定当前技能加成）。
2. **相克 = 增伤乘区**，是**属性配对**（攻方技能属性 vs 守方属性/灵根）。
3. **双属性技能 = 桥接器**（同时参与相生与相克），是卡组的"润滑剂"。

### D-3 神通成长（境界 × 技能）

- **同一神通随境界自动增幅**："突破一大境界时，每种神通都会增幅到相应境界的数值。"
- 金刃：练气 4 → 化神 36（**约 9 倍**）⇒ **境界是技能数值的主乘数**，与凡人"境界=碾压"一致。
- 神通有 **所需灵气牌 / 属性 / 词缀**；有"使用次数限制"、"根据相生相克变化"、"根据上一个技能属性变化"三类特效。

### D-4 功法 / 法宝 / 悟道（养成维度）

| 系统 | 关键规则 |
|---|---|
| **功法** | 共 **5 层**，突破层数越高效果越强；**品阶决定境界门槛**——人阶练气最多突破 3 层、地阶 2 层、天阶 1 层，**每提升一个大境界可多突破 1 层**；配置为**主修（定修炼速度）/ 辅修（仅战斗）/ 遁术（先手与逃跑）** |
| **法宝** | 五品阶：符器→法器→法宝→纯阳法宝→通天灵宝；同阶分上中下三品；属性含**金木水火土 + 剑 + 神识 + 混元**；**武器=主动技能**（类似炉石英雄技能，有 CD）、**防具/饰品=被动**；器道研修后最多装备 2 把武器 |
| **悟道** | 11 方向的技能树，论道攒"思绪"→闭关感悟→"悟道点"解锁 |
| **丹毒** | 服药累积丹毒，>50 每回合抽牌 -1，>70 抽 -2，>100 施法 50% 失败，=120 **毒发身亡** |
| **战斗前** | 三选项：**神识探查**（看对方装备功法）/ **战前准备**（调配置/吃药）/ **逃之夭夭** |
| **突破** | 大境界突破是**特殊关卡（boss 战）**：如筑基需用聚气/运气术优化灵力结构、压缩灵气，使"筑基点数"达 100 才算成功 |

### D-5 觅长生灵根的"陷阱"（本项目别照抄）

- **天灵根在觅长生近乎是"最优解"**（"遇事不决天灵根"），因为连击流占比虽大，但天灵根爽度与成长都更稳 ⇒ 觅长生其实**没做好"多灵根的取舍"**。
- 而**凡人恰好提供了那个取舍**（炼虚需五行合一）。⇒ **本项目应取凡人的"取舍结构" + 觅长生的"权重/连击机制"**，而不是直接抄任一方的灵根强弱曲线。

| **相克表** | `KE = [1,4,3,0,2]`（金克木/木克土/水克火/火克金/土克水） | `mapgen.js:91` |
| ⭐ **异灵根表** | `DUAL = {'0\|3':'雷','1\|2':'风','0\|2':'冰','3\|4':'暗'}`（相冲/相合→异灵根）+ `VEIN_VARIANT_ORDER=['雷','风','冰','暗']` + `VARIANT_RGB` | `mapgen.js:92,97,101` |
| **五行配色** | `ELEMENT_RGB` 已下发前端（`mapgen-server.js:281`） | `mapgen.js:98` |
| **灵脉主灵根** | 每个群落 `communityOf` 播一个**主灵根** `el = hash01()*5` | `mapgen.js:2027` |
| **群落内五行发育** | 相生支脉繁荣（`SHENG[el]`）、远相生（`SHENG[SHENG[el]]`）、相克制衡→异变（`KE[el]` + `dualOf`） | `mapgen.js:2053-2066` |
| **地貌池** | `LANDFORM[el]`（5×5）、`VARIANT_LANDFORM`（雷/风/冰/暗） | `mapgen.js:102-112` |
| **资源维度** | `RES_ORDER=['粮','木','矿','渔','炭','灵','丹','器']`（8 种） | `mapgen.js:690` |
| **领地半径** | `domainRadiusOf`（city8/town6/sect3-8/village4/fishing4/poi0），前端镜像 `domainRof` | `mapgen.js:1322` |
| **实体类型** | 世界里只有：聚落/宗门/秘境/道路/灵脉。**没有任何"人"、没有任何"战力"字段** | `mapgen.js` |
| **弟子** | `PlayerSect.disciples` **只是一个整数**（"P0 只存一个整数，不存名单"） | `docs/玩家信息表设计.md` §2.3 |
| **Tick 空壳人物 job** | `SectCultivation`（弟子修炼）/`Lifespan`（寿元）已声明并注册为 L0/Cpu，但**只写 bytesIn/bytesOut，真实公式待 P2** | `Time/TickJob.cs:41-47`、`ITickExecutor.cs:95` |
| **确定性纪律** | 全随机走 `hash01(i,j,salt)` 纯函数；**禁 `Math.random()`/`Date.now()`** | 引擎 |
| **落库纪律** | ⚠ `PruneExcept` 会静默删 `Data` 表 ⇒ **战斗状态/战报必须独立成表**（同 `WorldLedger`/`PlayerSectStore`/`CityStateStore`） | `Storage/` |

**三条硬结论：**

1. **五行 + 相生相克 + 异灵根，本项目已 100% 就绪**，且是**纯函数常量表**——把觅长生的"相生连击 / 相克增伤"搬过来，**不需要新增任何常量，只需要写一层"伤害计算"纯函数**。这是本次调研最大的红利。

2. **"灵脉有主灵根"是一个两作都没做的机制**。凡人/觅长生的灵根都长在**人**身上；本项目**灵根长在地上**（群落主灵根 + 相生支脉 + 相克异变）。⇒ 可以做"**主场作战加成**"：*火灵根修士在火灵群落里战斗力上升，在水灵群落里被压制*——**这是本项目独有的、两作都没有的战场维度**（等于把"地形"升级成"属性相性"）。

3. **战斗的"人"和"场"都是空的。** 世界里没有人（只有 `pop` 一个数），没有战力字段，`SectCultivation` 也是空壳 ⇒ 战斗系统**无法只靠加字段实现**，它**必然依赖"人物系统"先落地**（哪怕是《人物系统-资料调研》§六路线 C 的"聚合统计层"）。**这是本调研的第二个关键依赖。**

## 六、三条候选路线（含我的倾向）

分歧点只有两个：**战斗粒度**（谁在打）、**玩家参与度**（管不管出牌）。

### 路线 A：宗门对宗门 · 自动结算（最轻）

- 战斗 = **一个 Tick job**：输入双方"宗门战力向量"（境界分布 × 弟子数 × 资源），输出胜负 + 战损 + 战报。
- **玩家不介入**，只在事后看**战报**（编年/日志）。
- **优点**：零前端改动；N = 宗门数；与 Tick 天然契合；**离线也在推演**（本工程最擅长的模式）。
- **缺点**：**没有"斗法"的爽感**，五行克制只能体现在"战力系数"里，很隐晦。

### 路线 B：个体聚焦 · 可操作卡牌战（最重，觅长生式）

- **聚焦层修士**（玩家核心弟子/天命者/掌门）拥有一套**完整的战斗数据**：灵根权重、功法层数、法宝、神识、遁术、灵气牌池。
- 战斗是一场**回合制卡牌对局**，玩家**每回合抽牌出牌**，走 `WS` 实时通信（新帧位）。
- **优点**：表达力最强，五行相生相克能做满；最"修仙味"。
- **缺点**：⚠ **与一号约束正面冲突**——一场战斗几十个回合、每回合一次同步往返，而且**随机抽牌必须严格可复现**（否则 replay/回归判据全崩）。工程量与人物系统路线 B 同量级。

### 路线 C：LOD 分层战斗（我的倾向）—— "聚合战斗 + 聚焦斗法"

一句话：**大部分战斗是一个公式，少数战斗是一场对局。**

| 层 | 谁 | 怎么算 | 玩家看到 |
|---|---|---|---|
| **L-agg（聚合层）** | 普通宗门间/攻城/清剿 | **一个 Tick job**：战力向量 + 五行相性 + 少量随机 ⇒ 胜负/战损 | 战报（编年/地图变化） |
| **L-focus（聚焦层）** | 玩家宗门核心战 / 天命者 / 剧情战 | **回合制卡牌斗法**（五行灵气牌 + 相生连击/相克增伤） | 实时对局 |
| **L-render（呈现层）** | 前端 | 地图上兵力/战雾/战斗动画（复用现有实体通路） | 地图 + 战报 + 对局面板 |

**倾向 C 的三条理由：**

1. **它把最"贵"的部分（实时卡牌战）限制在少数战斗上**，其余全部摊销成确定性纯函数——**既不放弃斗法体验，也不让每 tick 被战斗拖死**。（与《人物系统-资料调研》§六路线 C 同构，可直接对齐两组件的 LOD 边界。）
2. **它正面回答一号约束**：每 tick 的战斗 job 数 = 正在交战的对数（可控），**与总宗门数/总人口无关**。
3. **它复用本工程已验证的两个范式**：LOD（小地图 L1/L2/L3）+ `ext` 覆盖层；**不是新范式**。

⚠ 路线 C 的关键设计问题：
- **"自动战斗必须可复现"**——随机源只能用 `hash01(seed, tick, battleId, salt)`，且**必须与用户操作序列一起构成 replay**（memory 铁律："整局游戏 = seed + 操作列表"）。
- **战场状态牌堆必须由纯函数推进**（抽牌 = `hash01(battleId, round, drawIdx)`），**不能有服务端可变 RNG 状态**——否则离线/在线两条路径会分叉。

## 七、必须由你拍板的问题

| # | 问题 | 我的建议（仅建议） |
|---|---|---|
| 1 | **战斗粒度**：个体 / 部队 / 宗门？（决定走 A/B/C） | **C（LOD）**——先做聚合层跑通，聚焦层按需长 |
| 2 | **玩家参与度**：自动结算看战报 / 可操作卡牌对局？ | 聚合层自动；聚焦层再考虑卡牌，**P0 先纯自动** |
| 3 | **灵根含不含异灵根**？ | **含** —— 引擎 `DUAL` 已就绪，**零成本**拿到雷/风/冰/暗（还能呼应灵脉异灵根） |
| 4 | **五行相生相克是否作为核心机制**？ | **是**——这是本项目"白捡"的差异化；相生=连击、相克=增伤（觅长生口径） |
| 5 | **要不要"灵气牌池"**？ | **聚焦层要，聚合层不要**（聚合层用"五行相性系数"即可） |
| 6 | **灵根是"权重向量"还是"等级"**？ | **权重向量**（觅长生口径）。⚠ 但强弱曲线取**凡人的取舍结构**（多灵根前期弱后期强），别抄"天灵根最优" |
| 7 | **灵根可否后天改**？ | **可**（`补天丹`/机缘），但要**留下"改过"的痕迹**（编年） |
| 8 | **"灵脉主灵根"要不要参与战斗**？ | **要**——主场加成，本项目独有维度（§五结论 2） |
| 9 | **战斗在何时算**：即时 / Tick job？ | **Tick job**（`dtTicks` 摊批，遵守 L0 红线：只写可变派生层） |
| 10 | **确定性要求**？ | **要**——同 seed + 同操作 ⇒ 逐 tick 逐战斗可复现（本工程铁律） |
| 11 | **战斗依赖"人物系统"吗**？ | **依赖**——个体战斗需先有个体实体；聚合战斗可先用"宗门战力向量"过渡 |
| 12 | **首个可玩的战斗场景是谁打谁**？ | 建议**立宗防守战**（玩家宗门被妖兽/邻宗围攻）——最能验证"地图+战斗+战报"闭环 |

## 八、你确认后，下一份文档会写什么

拿到 §七 的答复后，我会出《战斗系统-实施方案》，目录预览如下（方便你提前否掉不想看的部分）：

1. **数据模型**：`Battle` / `Combatant` 字段（灵根权重向量 / 境界 / 功法 / 法宝 / 神识 / 遁术）；哪些提列、哪些进 JSON、`v` 版本号
2. **五行规则层**：`SHENG`/`KE`/`DUAL` 复用；相生连击表、相克增伤乘区、**双属性桥接技能**；与灵脉主灵根的"主场系数"
3. **战斗结算**：聚合层的纯函数（战力向量 + 相性 + `hash01`）；聚焦层的牌堆推进与回合机
4. **Tick 接线**：战斗 job 的 `Kind`/相位/`dtTicks` 摊批；`OnJobApplied` 挂钩（⚠ 回调不得抛）
5. **存储**：`BattleStore`/`BattleLogStore` 独立表（避开 `PruneExcept`）；战报的 append-only 结构
6. **协议/前端**：战报并进 `settle` 包还是新帧；对局面板的帧位与交互
7. **判据**：离线可直调的断言（确定性哈希、相生连击可复算、相克乘区单调、战报与状态一致）
8. **风险与回退**：同步门闩占用、与人物系统/Tick 的耦合、随机源分叉
