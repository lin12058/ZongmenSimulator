## 0. 需求

原始（用户原话，逐条照抄）：
1. **B 方案**（角色有独立地图坐标，不是在聚落旁挂个数字）。
2. 地图上有很多人或者小队，**同一个格子上面有很多人**。
3. **按 chunk 进行传输**。
4. **点击对应的格子**时显示上面人物列表。
5. 列表**按修为（战斗力累计和）从高到低**排列。

Q1~Q4 拍板后追加的口径（**推翻了 v1 的三处**）：
- **Q1** 人**优先聚集在聚落/宗门格**，**小部分**随机散布（散修）。
- **Q2** 详情**按「点击的那一格」取，不按区块取**；区块只带「这一格上有多少人/多少战力」；
  **只在开启「人力热力图」时**才要这一层。**战力显示 = 点击格 + 一个区块距离内的全部格，
  按「距离点击由近到远」逐格变淡**，且**只在点击那一下显示**。
- **Q3** 开局人人是筑基期（演化还没接），**战力只看基本属性**（神识/法力之类），**不看境界**。
- **Q4** 单位是**小队**（当前 1~12 人）；「一个人」= 规模 1 的小队，**没有「单个人」这个独立概念**。

## 2. 设计

### 2.1 谁在哪一格（Q1）
- **主聚集**：遍历本块（区块）覆盖的**区域格**，取 `MG.settlementsFor(i,j)`（含 ext 玩家宗门）；
  每个聚落**落在自己的中心格** `(st.q, st.r)`。
- **副散布**：对块内的**陆地格**（`fields()` 非水）按 `hash01(seed,'ppl',q,r)` 抽极少数格落散修
  （约 6% 的陆地格，每格 1~2 人）。散修不依附聚落。

### 2.2 每格多少人 / 多少战力
```
n(tile) = clamp(round(pop / PEOPLE_PER_HEAD), 0, 64)     // PEOPLE_PER_HEAD = 120, 硬上限 64
散修格   n = 1 + (hash01(...)<0.5 ? 0 : 1)               // 1~2
```
`n` 的硬上限 **64** 是被 §2.3 的索引打包绑死的（每格 6 位槽位），改上限必须同步改索引公式。

### 2.3 单人索引（双射 → 人不会在格之间串味）
```
index(q,r,k) = (((q + 524288) * 1048576) + (r + 524288)) * 64 + k     // k ∈ [0,64)
```
- **双射**：不同 `(q,r)` 必得不同区间 ⇒ 同一 seed 下「人」全局唯一、可复算。
- 值域 ≈ 2^46 < 2^53 ⇒ 前端/JSON 都不溢出。
- ⚠ 地图上的「人」与 `GET /api/characters?offset=0..N`（众生录）是**两套索引空间**，
  不保证同一批人。统一索引空间是后续工作（届时众生录改为读同一派生）。
- ⚠ 人物 id 仍是 `c` + 零填充数字，**绝不**用 `{i}_{j}_{k}`（引擎会反解前两位为区域格，见红线）。

### 2.4 战力（Q3）
纯函数、可复算，**只吃基本属性与资源**（不看 `realm`）：
```
power = round(
    3.0*attributes.shenshi  + 2.0*attributes.gengu   + 1.5*attributes.wuxing
  + 1.5*attributes.xinjing  + 1.0*attributes.qiyun   + 1.0*attributes.meili
  + 0.5*resources.qi        + 0.25*resources.qixue   + 0.33*resources.jingshen )
```
⚠ 境界权重**刻意不做**（Q3：「开局人人是筑基，演化还没接」）。等 `SectCultivation` 接通后
再补「境界绝对优先」项——见 §8 待办。战力只作**展示口径**，不改任何既有字段。

### 2.5 小队（Q4）
- 每格把 `n` 个人切成小队：规模 = `1 + floor(hash01(seed,'sq',q,r,k)*12)`（**1~12 人**，当前口径）。
- 小队战力 = 成员战力之和；小队代表 = **战力最高的成员**（点开名单时可跳到众生录）。
- 列表按战力**降序**；没有「单个人」条目——人只作为小队成员出现。

## 3. 协议

| 项 | 定义 |
|---|---|
| 图层位 | `TileMask.People = 1<<5`，`All = 0x3F`（**必须**同批改 §6 的 5 处硬编码 31/30） |
| 载荷 | `PeopleData { List<PeopleTileDto> Tiles }`；`PeopleTileDto { int Q; int R; int N; long Ps }`（**稀疏**：只带 n>0 的格；`Ps` = 该格战力总和） |
| 落位 | `TileResponse` 字段 **15**（10~14 已占）；`Revs` 由 5 元 → **6 元** |
| 不落库 | People 层**绝不**进 `_mem`/SQLite/`Data` 表（纯派生；一旦落库，淘汰后 `ReadSqlBackfill` 会把旧包捞回来） |
| 生成 | 请求时现算 + 进程内 LRU（key = `seedprefix:ca:cb`），**零持久化** |
| 鉴权 | 与 Settle/Poi/Comm 同口径：未登录从 mask 剔除并记 `DeniedMask` |

### 3.1 点击详情（Q2）
```
GET /api/people?seed=&q=&r=       → gzip JSON
{ schema, seed, q, r, n, ps,
  squads:[ { id, size, power, rep:{ index, name, realm, stage, power } } ]   // 战力降序
}
```
- 服务端链路：**核心 VM** 取落人格 `peopleAtJson(q,r)` → `{n, base}` → **角色 VM** 取
  `squadBatchJson(seed, base, n)` → 小队列表。两 VM 各借一次（`LeaseScope`）。
- 「1 个区块距离内按距离变淡」**不需要新接口**：热力图那层已经按块把每格 `Ps` 发到客户端，
  点击时**纯前端**从已加载的 `peopleData` 里取该点周围 `chunkScan`(=15) 格内的 `Ps` 逐格画，
  透明度随六边距递减，**1.2s 后自动消失**（Q2「只在点击那一下显示」）。

## 7. 红线与静默坑（本项目已有教训，直引）

1. ⚠★ **任何改变该层内容的服务端改动必须 `BumpBlockRev`**，否则客户端带旧 `lastRevs` 重拉被判
   「未变化」⇒ 永久陈旧（不报错）。
2. ⚠ People 层**纯派生 ⇒ 绝不落库、绝不进 `_mem`/SQLite**；一旦落库，淘汰后 `ReadSqlBackfill`
   会把旧包捞回来（表现为「人一会儿又跳回原样」）。
3. ⚠★ 人物 id 保持 `c…`，**不要**用 `{i}_{j}_{k}`（引擎会反解前两段为区域格，会被路网误读）。
4. ⚠ 新 JS 出口三处必挂：对应 `JsvmModule.Invoke` 的 switch / WS 路由 / 前端。`characters` VM 与
   `core` VM 是**两个独立 V8**：落人格走 `core`（有骨架/地形），战力与小队走 `characters`
   —— **不要**指望一个 VM 里同时有两者（`AcceptsExternalSettlements=false`）。
5. ⚠ 改引擎 js ⇒ ① `sync_preview_inline.mjs --check` ② 重启服务端 ③ 载荷变则停服清 `db/zongmen.sqlite*`。
6. ⚠ 同一文件**一次只发一条 Edit**（多条并行只有最后一条生效，都回执成功）。
7. ⚠ 客户端对**已加载**的块不会自动重拉（`updateStreaming` 入队条件是 `!chunkData.has(key)`）
   ⇒ 热力图开关必须让「缺 People 层的已加载块」重新入队，否则开了开关什么也没有。

## 9. 实施回填（2026-10-11 已落地 · 判据全绿）

S1~S8 + F1~F6 全部实现；新增在线判据 `verify/check_people_layer.mjs`（11 条全绿）。
落地时对 v2 有 **4 处必要修正**（原文未预见，记此以免复踩）：

| # | 修正 | 原因（静默故障） |
|---|---|---|
| 1 | **People 层不走 rev 去重**：服务端改为「mask 含该位就每发必带」 | 该层是「热力图开关」的**临时数据**：关掉开关客户端丢数据，但 `lastRevs[5]` 仍记旧 rev ⇒ 再次打开时服务端按 rev「未变化」缺省下发 ⇒ 热力图**第二次打开永久空白**（且不报错）。见 `MapWorldService.GetTileBlock` 的 `wantPeople`。 |
| 2 | 前端 `loadChunk` 掩码是**剔位**（`if (!enabled()) mask &= ~PEOPLE`）而非加位 | `PB.MASK.ALL`(0x3F) 与 `CALC_MASK`(0x3E) **本已含** PEOPLE 位 ⇒ 关着必须剔掉，否则每块都白算一层。 |
| 3 | `w2`「liveSeeds 有界」判定改用**池容量**（新增 `stats.poolCapacity = MaxSeeds × Scope 数`） | tile 请求现在也借 `characters` VM（双 VM 架构）⇒ 一个 seed 占多个 VM，拿 `MaxSeeds` 直接比会假红。 |
